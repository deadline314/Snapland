# Welcome-game photo thumbnails

Successful, non-practice welcome minigames attach up to three readable 320×180 saved gameplay frames to their ordinary album record. Devil results share the same frame references with the corresponding devil record. The save path belongs to the result/session; completion code only stores references. Replays replace the frame list in place, so they do not duplicate collection or grant progress. Failed and practice results never attach frames.

On load, legacy devil records can inherit an already-collected ordinary photo's readable frame list. This is a metadata migration only: it does not award either photo. A missing, unreadable, wrong-sized, or malformed image is skipped. Album loading caps path candidates and file bytes before image decoding, checks PNG dimensions before decode, deduplicates paths, and keeps decoded game thumbnails cached for the open book. The album UI also accepts bounded general PNG records (up to 16 MiB, 4096×4096 and four million pixels) such as older exploration snapshots; this presentation path does not relax the minigame record validator.

The bounded CPU regression is `res://game/tests/test_main_photo_thumbnails.tscn`. It checks Main's success/practice/failure/replay gate, shared ordinary/devil paths, legacy migration, missing/malformed fallbacks, path caps, duplicate suppression, and decoder avoidance for oversized IHDR dimensions. Godot's PNG decoder logs engine errors for the deliberately CRC-valid broken-zlib fixture; the application detects and rejects it. Those engine diagnostics are expected from this negative case and are not evidence of a clean error log. Tests are headless; they do not establish an in-game visual result.

Reference context actually read for this change: Nintendo's [New Pokémon Snap product page](https://www.nintendo.com/us/store/products/new-pokemon-snap-110735/) describes the album/Re-Snap loop; Microsoft's [Xbox Accessibility Guideline 104](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/104) covers readable access to speech and cues; the [GDC Vault Shipbreaker interface session description](https://www.gdcvault.com/play/1027158/Cutting-Apart-The-Diegetic-Interface) discusses balancing diegetic and conventional interface (the full talk was gated); the [USJ play experience page](https://www.usj.co.jp/web/en/us/areas/super-nintendo-world/play-experience) describes optional interactions and collections; the [Adobe Character Animator walk behavior reference](https://helpx.adobe.com/dk/adobe-character-animator/desktop/behaviors/learn-more-about-behaviors/body-directly-controlled.html) and [Spine ghosting guide](https://us.esotericsoftware.com/spine-ghosting) were consulted for the separate character-motion work. Those movement pages do not validate this album UI.
