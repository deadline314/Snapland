# 衣料資源驗證與有界快取

2026-10-26（Asia/Taipei），ART-18。這次只改資源持有與失效處理，不改原畫、服裝輪廓、動作時序、頭髮錨點、免費收藏或保存格式。

## 研究與決策

| 實際閱讀的一手來源 | 採用與界線 |
|---|---|
| [Godot 輕量物件與 RefCounted](https://docs.godotengine.org/en/stable/tutorials/best_practices/node_alternatives.html) | 衣料是資料與合成服務，延續 RefCounted，不為每格建立場景節點；引用消失即可釋放。 |
| [Godot Image](https://docs.godotengine.org/en/stable/classes/class_image.html) | 解碼後畫布佔記憶體，不能用磁碟 PNG 大小當常駐量；保持原 PNG RGBA 合成方式。 |
| [Godot ResourceLoader](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html) | 原始非資源資料用 FileAccess；不把 `.pngdata` 換成會經圖片匯入重映射的路線。快取與資源完整性驗證是不同責任。 |

三頁為文字閱讀；沒有宣稱觀看官方示範動畫。前期另讀 Godot cutout、Spine mesh 與 Dead Cells 作者的管線說明，未採用其身體拆件／3D 輸出，保留已批准的完整 2D 人物。

## 契約

1. 首次使用仍逐格核對整套 172 個實際請求：身份、覆蓋、原人物 RGBA、PNG 位元組、格式與 280×360 畫布。任何一格失敗即拒收整套。
2. 每格驗證完成後釋放解碼結果，只保存精確位置與指紋。播放時按需解碼，最多保留近期 12 格。每次回載都再驗指紋；暖命中不重讀、不重解碼。
3. 讀檔有明確長度上限；先確認 PNG 簽名、IHDR 和固定尺寸，再讓解碼器處理內容，避免錯誤的巨幅宣告造成額外配置。解碼後再驗實際尺寸。
4. 失敗前不碰合成目標；失敗時清掉整套資料與衣料快取，診斷包含實際動作／方向／格次。後續請求不持續重讀壞檔或反覆新增錯誤。
5. **下游最終貼圖也必須看見失效。** 穿衣貼圖的快取身份包含衣料服務身份與整套驗證狀態；回退後不能再命中先前的穿衣結果。替換衣料服務也不借用前一個服務的最終貼圖。
6. 來源、原人物、髮帽與頭部所有權不由快取服務修改。錯誤目標畫布不畫，也不因此拒收有效衣物。

這是載入／回載時檢查，不是持續監控所有磁碟資產。發行包內素材按不可變資源使用。數值是衣料解碼畫布的穩態快取，不包含目標畫布、解碼暫存、最終 ImageTexture、引擎、VRAM 或整個程序 RSS。

## 可重現驗證

- 舊版：172 張 RGBA8 畫布，共 69,350,400 bytes（66.14 MiB）。新版：首次整套檢查後不保留解碼畫布；正常使用至多 12 張，共 4,838,400 bytes（4.61 MiB），減少 93.02%。
- 同一原人物與衣料先後合成 172 格，舊版／新版每格 RGBA SHA256 完全相同；另以正式渲染器驗既有全套組合。
- 正向與反向走遍 172 格，共 344 次實際合成均與獨立 PNG 合成相同；暖命中 512 次沒有增加解碼。另驗釋放快取、重新載入、原人物未被修改與錯誤目標畫布。
- 真正建立隔離的原始資產與有效清單，驗證後淘汰該格，再實際刪除或改一個位元組。失敗不得留下部分衣料，鄰格也不能繼續使用。事先暖過的最終角色貼圖同樣須回到完整原人物。
- 原先遺漏最後一條時，真實反例兩次失敗，已保留紀錄；修正後同一反例通過。偽造巨大 PNG 尺寸但清單指紋相符的反例，也在解碼前拒收。
- 正式衣櫃以鍵盤／按鈕事件走試穿、穿戴、八組移動輸入、降低動態、換回原外套與保存後重載；保存 12 張實際畫面與當下快取值。
- 最終 ELF 的嵌入 PCK 在只有專案設定與外部驗證腳本的隔離目錄，重新跑全部 172 格；沒有散落玩家程式／PNG。這與真正執行成品的冷啟動檢查分開記錄。

本地重跑入口為 `game/tests/test_garment_cache.gd`；整套驗證器已加入該檢查。素材與動畫品質仍依 ART-17／18 原票，不因這次快取改善升格。
