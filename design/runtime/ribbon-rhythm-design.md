# 彩帶節拍：舞台、節奏與視覺來源

## 目標與差異

`game-006` 是正面觀看的 2.5D 小型歌舞廳演出。玩家依八拍完成左右踩步、躍起與兩次按住的彩帶橫掃；舞台上的八盞踏燈表示已完成、目前與未來拍點，兩張預告卡仍展示接下來的動作。它與噴泉跳拍的近距離水池、三次單一跳躍目標不同：本作把左右位移、短促跳躍、持續輸入、雙角色演出和完整舞台彩帶編成一段表演。

舞台以深色天鵝絨簾幕、扇形簾楣、黃銅台口、斜向木地板與踏腳燈構成。四盞固定燈的色溫隨 dawn、noon、dusk、night 改變；光束不移動、不晃動分數。地板的三組弧形踏點分開左、中、右落腳區。主角在中央表演，小角以較小的完整身形站在右側翼；彩帶在角色身後依方向、跳躍圈和持續橫掃畫出不同弧線。彩帶只在動作完成或按住期間出現，沒有通用粒子噴發。

玩家全身姿勢仍使用 AvatarRenderer 的既有資產。實際可用的動作為八方向 walk、front jump、front wave，以及舊動作圖集的 idle 和 celebrate；manifest 明確只為 jump 提供 front 方向，wave 也只有 front。沒有 traveller dance 動作。左／右步使用實際 walk 方向，躍起使用 authored front jump，持續橫掃則使用既有 front wave 靜態姿勢，讓彩帶承載掃動。小角使用 CharacterAnimationLibrary 中現有的 `imp/idle/front` 七幀循環和 `imp/dance/front` 七幀單次序列；只有模型接受第八拍並以成功結束時，才播放 dance。Session 會讓完成畫面保留最多 1.30 秒，讓玩家看見舞蹈後才送出一次結果；降低動態時改為 0.18 秒的靜態完成姿勢。暫停會凍結剩餘演出時間與畫面，恢復後接續同一段舞蹈；重試與離開會清除尚未送出的完成狀態。失敗仍直接結算，失敗與重試不會觸發或沿用完成動作。

## 八拍輸入與計分

| 拍 | 輸入 | 表演 | 留按 | 重拍 |
|---:|---|---|---:|:---:|
| 1 | 左 | 左踩步 | 點按 | 是 |
| 2 | 右 | 右踩步 | 點按 | 否 |
| 3 | 跳 | front jump | 點按 | 否 |
| 4 | 左 | 左側彩帶橫掃 | 0.34 秒 | 是 |
| 5 | 右 | 右踩步 | 點按 | 否 |
| 6 | 跳 | front jump | 點按 | 是 |
| 7 | 右 | 右側彩帶橫掃 | 0.40 秒 | 否 |
| 8 | 左 | 收步 | 點按 | 是 |

八拍時間固定，首拍在 1.02 秒，後續每 0.94 秒一拍。一般判定窗為拍心前後 0.27 秒，拍心 0.105 秒內是精準；輔助模式把可接受窗放寬到 0.46 秒、留按長度誤差放寬到 0.24 秒。每次正確精準得 100 分，合拍得 60 分，重拍再加 25 分。八拍中至少六拍正確才算一般成功；漏拍、錯方向、過早輸入或提早放開都會記錯。錯方向不會自動跳過本拍，玩家可在本拍結束前重新輸入。

惡魔成功需要八拍全數精準、所有重拍正確、零錯誤且未開輔助。輔助只放寬輸入與留按容差；提示仍是靜態動作圖示、文字、重拍標籤和進度線，玩家必須親自輸入八拍。沒有動作的等待只能以失敗結束，不會自動得分或勝利。模型每次只接受最多 0.25 秒的時鐘推進，拒絕非有限時間值並快取穩定 snapshot。

## 操作畫面與可讀性

設計座標為 1280×720；共享 HUD 顯示標題、目標、分數、時間與通用操作，view 不再重畫分數、時間或另一段長說明。八拍燈位於舞台木前沿，與上方 HUD 保持間距；控制按鈕標示方向鍵、A/D、Space，並可用滑鼠點按或按住。台口操作區限制在 y=142..628；玩家和小角的全身畫面都在舞台範圍內。上下縮放保留比例並置中，滑鼠座標先換回設計座標。左右、跳躍的形狀按鈕有直接訊號；按下和放開各自傳出訊號，支援留按。

降低動態時停止彩帶生長、角色循環幀與所有裝飾動作。固定在畫面上的當前目標、後兩拍、八盞拍燈、方向形狀、重拍標記、分數和留按量尺仍提供相同資訊。小角保持不同於玩家的靜態 imp 身分；只有成功完成第八拍後的單次 dance 姿勢會凍結在最後一幀。命中後的彩帶停在當前完成弧線，無震動、閃白或自動演出。

## 實作介面與驗證界線

模型 API：`reset(assisted, time_phase)`、`press_action(action)`、`release_action(action)`、`step(delta)`、`snapshot()`，另有 `retry()`。snapshot 提供固定八拍、節拍音訊序號、兩拍預告、評級、得分、錯誤、成功條件與完成彩帶。view API：`configure_avatar(appearance, equipped)`、`update_frame(snapshot, time_phase, reduced_motion)`、`screen_to_design(point)`、`playfield_rect()`、`bounds()`、`avatar_bounds_for_pose(pose)`，並發出按下／放開訊號。

局部 headless 測試涵蓋過早與錯向、按住重複、短留按、重試重置、完美八拍、輔助模式仍須輸入、閒置不勝、快取、時鐘上限和非有限時間；Session 生命週期測試另外驗證成功延後結算、失敗即時結算、暫停／恢復、重試、離開與降低動態；view 測試涵蓋設計座標、縮放、所有選用姿勢邊界、鍵鼠訊號及降低動態時保留的提示。這些自動測試只證明模型與座標／訊號契約；沒有被描述成原生遊戲試玩、畫面品管或 GPU 驗收。


## 本輪原生驗收與限度

Root 以最新故事／HUD 相依與實際 Session.start_game 路徑跑過兩部 GPU 流程，正式八次鍵盤動作與兩次留按自然取得900分／八次精準／零錯誤及普通、惡魔照片；降低動態私人練習以八次指標輸入同樣取得900分，沒有改寫收藏、成就、任務、錢幣或服飾。正常流程2577幀／42.95秒，四分之一速度流程4543幀／75.716667秒，均60FPS、exit0、無SCRIPT ERROR／ERROR／FAIL。影片包含菜單、錯按後暫停確認重試與結果，不是遊戲回合時長；私人操作均0.25倍，結果畫面回到1倍。

最後一拍後確實仍有存活Session與1.30秒演出，拍下start/mid/late，小角七張既有舞蹈圖能播完。真實HUD暫停使演出elapsed與伴舞幀保持不變，恢復後等剩餘時間再發結果；一般finished連線完整記錄一次發送，不用one-shot掩蓋第二次發送。降低動態保留0.18秒靜態完成姿勢。Root逐一看過兩輪各25張截圖。原先一次四分之一錯按驗收曾未記到輸入，原因沒有被證明；保留該失敗與trace，新整合版本兩輪錯按／重試均通過，沒有移除斷言或改成直接設定模型。

Root五組相關CPU驗收：model42、view138、startup3、Session lifecycle61、既有minigames81，皆exit0、無錯誤。headless整合測試先把Window設為1280×720，再建立Session；先前64×64預設使HUD物理字級被放大，並非已證明的正常遊戲視窗故障。沒有更動測試選擇器或HUD生產字級來讓測試變綠。

舞台與小角辨識已有改善；主角仍借用既有walk／jump／wave／celebrate，沒有新主角dance素材。完整自然編舞、音樂試聽及最終舞台美術仍需要各自驗收，這些局部流程不等於整款遊戲或全園區達到公開品質。嵌入教學舊畫面待各款定稿更新。

Root 已實際播放正常與四分之一速度兩部影片至 ended=true，沒有使用加速播放或以截圖代替影片檢視。

## 2026-10-23：跟拍配樂、數拍前奏與判定呈現（SG-21）

### 問題

節拍只靠每拍一個提示音疊在共用遊戲曲上，背景音樂與 0.94 秒拍距無關；第一拍前只有約一拍準備，玩家無法先感受速度。提示卡只說「做什麼」不說「何時」；漏拍同時計入「錯誤」，HUD 出現「失拍 4 錯誤 4」；彩帶回合只約 9 秒卻顯示 60 秒倒數。

### 改動

- **遊戲自有配樂**：依同一張拍表合成原創伴奏（無取樣）：三下木魚數拍、每個動作拍落在鼓與馬林巴音上（左／右／跳各有音高）、強拍加拍手、半拍沙鈴、兩拍一個低音、留拍時有與按住長度相同的上揚彩帶聲，最後一拍後的琶音與和弦收在 1.3 秒謝幕內。彩帶回合播放時共用遊戲曲淡出，結束後恢復。
- **同一時間基準**：規則時鐘跟隨配樂的實際播放位置（播放位置＋上次混音後時間－輸出延遲，Godot 官方做法），並與遊戲時間互相核對；音訊時鐘不可用（例如無聲測試驅動）時改用畫面時間，不會加速或跳拍。
- **看得到拍心**：數拍期間舞台顯示 3、2、1 圓章；當前提示卡與腳燈有兩拍前開始收縮的圓圈，縮到圖示即拍心；判定牌顯示精準／合拍與「早／晚幾毫秒」或失拍；燈具在每拍輕閃（降低動態時關閉，收縮圈保留）。
- **計分說明**：HUD 分開「漏拍」與「錯按」，時間欄改成「預備 n／第 n / 8 拍」；規則文字由模型常數產生（精準 ±105 毫秒 +100、合拍 ±270 毫秒 +60、重拍 +25、輔助 ±460 毫秒）；結算列出漏拍、錯按次數與本次資格原因。
