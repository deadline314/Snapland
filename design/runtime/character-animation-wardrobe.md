# 角色整套動畫與服裝分層研究

## 2026-11-11 小角停步後以完整姿勢回正面

小角在巡路停止後使用 `settle/right` 或 `settle/left` 的四個完整來源姿勢：側身雙腳落地、骨盆與胸肩轉向、近正面收手，以及正面叉腰。兩段均為有限 10 FPS、共 0.4 秒，巡路根在整段保持不動；動畫結束後回到既有正面站姿，留出 0.6 秒安靜窗口再允許個性小動作。既有行走距離相位及其餘三位人物保持不變。

圖集沿用全身側向動作註冊程序，改以明確 action、FPS、loop 與可選 `return_direction` 描述有限動作的收束。來源固定四格中心、共用列地面與單一 0.395 縮放，沒有逐格鞋底重置、鏡像、拆肢或透明混合。收勢來源與八張行走來源分開，既有圖集資料可逐項比對相同。

`return_direction` 僅允許有限動作及八個已知方向，從素材庫入口統一驗證；詢問可用性、影格數、時間及實際載入都拒絕錯誤資料。NPC 播足最後一格後使用該方向恢復站姿，不會誤求缺少的側向待機。缺少可用收勢時保留既有正面待機回退；互動可中斷，暫停不補播，降低動態沿既有規則恢復完整人物。現有來源／貼圖／動作快取上限不變。

四份原畫逐次修正末格手勢與尾巴所有權、轉向中尾巴從身後通過，以及近正面與末格的領巾垂片。第三版原生畫面發現領巾缺口後由第四版取代；兩版原生日誌／姿勢分別保存，最終正常與慢速錄影重做，不混用不同來源當成同版驗收。八張最終收勢原生圖逐張核對，正式世界另檢查八張可見腳底；測試涵蓋中斷、暫停、安靜窗口與錯誤回正面資料。局部過渡改善不代表全角色起停／八方向、換裝或連續自然度驗收完成。

## 2026-11-11 票票的左右步態與互動標記跟隨

圖集的原始格距是 416px，固定邊界為 `(48,464,880,1296,1712)`，角色根 X 為 256、672、1088、1504；不是將整張寬度平均四等分。共用來源縮放 `0.432`、每列共用地面，保留姿勢重心，沒有逐格鞋底置中或獨立放大。原有正面 `walk_candidate` 仍獨立保留，不會被當成正式行走。

共用 `authored_npc_patrol.gd` 以有界、有限數值的角色配置管理範圍、速度、兩步距離與休息；未知欄位或不合法值拒絕整次重設，保留原狀態。小角沿原設定；票票從原點只向廣場內側走 1.2m 再返回，速度 0.9m/s、兩步循環 1.2m、起始停留 2 秒及端點休息 4 秒，避開原點左側高起路面並錯開其他角色節奏。左右整段來源可用才開啟，任一後段損壞即保持完整站姿。

三位 NPC 的互動標記在建立後、註冊自身浮動動畫前，保留世界位置並成為角色根的子節點。根負責巡路、標記的局部座標負責浮動，避免移動後指示仍留在出生點或錯誤保存世界座標。既有互動點亦繼續跟隨角色，其他設施標記不變。原生巡路檢視抽成共享角色版本，不用搬動 NPC 根或替換來源就能逐張觀察正式路線。

原生錄影採固定 Movie Maker 時間、Compatibility／llvmpipe 與 Dummy 音訊；錄影 FPS 不作即時硬體效能結果。逐張原生來源檢視及自動觀察仍與真人連續觀看、遊玩及試聽分開記錄，整套三張美術票依原條件驗收。

## 2026-11-11 小角的完整來源步態與地面短巡路

小角新增左右各四個全身行走姿勢，明確區分近腳接觸、遠腿通過、遠腳接觸及近腿通過。原圖保留完整四肢、反向擺臂與同一側長角；左向長角在追加身份核對後修正。前段重複半循環及長角鏡像的來源保存在票內原畫包，沒有當成正式版本。

圖集註冊沿用共用 NPC 切圖程序，阿浪既有輸出逐項相同。小角使用固定等分格中心與每列共用地面，不按每格鞋底重新置中；整張圖集採單一 `0.395` 來源縮放，保留原稿相對大小。沒有拆腿、鏡像播放、整身 shader 變形或逐格自動貼齊。

`authored_npc_patrol.gd` 專責短巡路 XZ 位移及有界相位；只有左右整段來源均驗證可用才啟用。以實際距離／0.36m 推進兩步循環，速度 0.36m/s，活動範圍為原點左右各 0.3m。地面不可用、落差過大或三條足跡射線碰到角色／牆壁時停步並轉回待機；大 delta 每次最多推進 0.1 秒，瞬移重新建立原點而不補播。既有 billboard 地面擁有者仍負責可見腳部 Y，不增加碰撞身體、隱藏骨架或導航快取。

對話與暫停不推進巡路；單次動作優先完成，之後回到站姿與個性待機。重新套用地面提供者不重置步態；降低動態、場景退出及重入恢復原本根位置和互動點。各實例獨立保存進度，沒有更改主角、票票或阿浪的姿勢及衣物資料。

本輪讀取 Godot 4.7.2 的 [射線起點在形狀內](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/doc/classes/PhysicsRayQueryParameters3D.xml)、[空間射線結果](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/doc/classes/PhysicsDirectSpaceState3D.xml) 與 [節點是否仍在場景](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/doc/classes/Node.xml) 的指定文字段落；未觀看來源影片。實際 StaticBody3D 阻擋、八姿勢可見腳部、互動點、暫停、對話及降低動態另有執行測試。

原生正常、真實四分之一速度／場景重入，以及隔離 PCK 均觀察左右八姿勢與停止後待機，沒有挪動 NPC 根位置取代巡路。正常全部八張姿勢圖、慢速接觸／待機及 PCK 左向圖已檢視；不宣稱真人遊玩、連續人類觀看或整套動畫自然度已完成。

## 2026-11-11 重建時保留換裝與遮擋原件

完整重建曾遺失服裝的 palette／variant 模式、整套姿勢義務、拍照八格的眼睛保護區，以及三格的頭部輪廓／前景手與相機遮擋，還會恢復已停用珊瑚背心的舊說明。這些是人工核對過的製作資料，不能從 alpha 外框重新推算。

`assets/characters/animation-authoring.json` 現在是上述資料的明確製作輸入；圖集建置器繼續獨佔來源區域與錨點。每組人工標記綁定原 PNG SHA-256、角色畫布、參考尺寸、腳底基準及每格來源區域／錨點／縮放；改圖後必須重審對應資料。建置時串流計算每份來源的雜湊一次，不增加遊戲執行時讀取或常駐快取。

使用 `python tools/build_character_animation_manifest.py --check` 核對；`--write` 只有全部輸入通過才寫入。更新服裝政策或人工遮擋時編輯製作輸入，不直接依賴生成 JSON 保存修正。缺少輸入、換了來源、幾何不符、越界標記、覆寫來源欄位、重複格或未知服裝模式都會使建置失敗，既有輸出保留。獨立坐姿、接球及額外方向仍沿既有保留規則處理。

本次重新生成的 JSON 與現行正式資料逐項相等；隔離專案使用重新生成的檔案進行原生衣櫃檢查。價格驗收改採實際可見且涵蓋標籤的底板背景；視窗調整透過擁有它的 Window，兼容沒有視窗管理器的 X11。價格門檻 4.5、精確價格、鍵盤焦點、禁購狀態及小視窗邊界檢查均保留。這是資料保存與既有衣櫃回歸，沒有新增角色原畫或宣稱整套 ART-18 已完成。

## 2026-11-11 共用逐格停留時間與完整回退

主角與 NPC 共用 `character_animation_timing.gd` 驗證及取樣時間；素材庫傳出 `frame_durations`，NPC 不再把全部姿勢當作等長影格。呼吸節奏只縮放同一播放時間，暫停不累積補播，有限動作播足末格後才回站姿。時間規格仍容許既有固定 FPS，沒有更改已驗收的姿勢或快取上限。

NPC 在接到動作前驗證整段 canonical canvas；即使壞掉的是後段影格，也拒絕整段並回到完整站姿，避免停在上一張手勢。反例先重現固定 FPS 的錯誤，再以不等長停留、暫停、循環、角色呼吸倍率、末格及損壞後段影格驗證。

實際讀取 [Aseprite 動畫文件](https://www.aseprite.org/docs/animation/) 的逐格時間入口，以及 Godot 4.7.2 的 [SpriteFrames 原始 API 文件](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/doc/classes/SpriteFrames.xml)（逐格長度）與 [AnimatedSprite2D 原始 API 文件](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/doc/classes/AnimatedSprite2D.xml)（更換動畫保留播放進度）。一般 Godot 文件及 Animation Mentor 頁面本輪回應 403，Aseprite Frame Properties 回應 404，均未列為成功閱讀；沒有觀看外部影片。

原生正常／四分之一速度只重驗票票既有四種正面動作；來源格自動觀察與抽樣 PNG 檢視不代表全角色動畫自然度通過。五份新步行原畫仍未形成可採用的完整循環，只有局部修正的單張相反接觸可作研究。來源、完整提示、尺寸及拒收理由見 ART-17 本次交付紀錄。

## 現況與目標

目前主角有八方向、每方向八格的逐幀走路素材；NPC 活動系統只提供四格短 routine（票票服務、小角舞姿、阿浪走路）。主角待機沿用步態第一格；招呼、拍照、互動與慶祝各只有一張正面姿勢，現有切圖忽略動作影格與方向，不能說成四方向動畫。這不代表各角色已具備獨立完整動畫集。票票、小角、阿浪都需要各自完整、辨識度不同的站姿與待機，以及按角色需要製作的動作。所有新增素材仍是需求，未製作前不得標成完成；單格或別角素材不能充當完整套。

## 建議方案：姿勢逐幀，服裝同步分層

主角與三位 NPC 的核心身體動作，採符合已批准完整比例與造型的八方向全身逐幀圖。每個姿勢都需維持同一角色的頭身比例、臉、四肢、鞋底與服飾辨識細節；不能用拆腿拼裝、旋轉／鏡像錯方向或重複格數來充數。主角八方向步態可先以每方向 16 個有實際動作差異的姿勢作候選標準，含兩步交替的 contact、down、pass、up 與有意義的過渡姿勢。這是待逐方向視覺驗收的製作目標，不代表現有八格已升級或 16 格天然合格。

服裝和配件以相同 `角色 × 動作 × 方向 × 影格／時間` 對齊。替換外套、帽子、髮型或飾品時，替換該格對應部件；不另開獨立計時器。每個影格要能記錄 head、hand、feet 錨點和可變 draw order：腳底維持角色基線；帽子遮住髮頂；前後手、相機、包帶與衣襬依姿勢改變前後層；後髮與前瀏海分層。禁止假定所有影格共用一個固定前後順序。角色身體必須完整保留，髮、衣與配件只能疊合到可見身體，不得留下缺腿、斷手或空洞。

呼吸由胸肩與衣服細節的小幅姿勢變化表達，不把整個人縮放當呼吸。待機節奏慢，眨眼、視線、整理衣物等小事件間隔開；角色不是不停表演。次級動態只限髮尾、裙襬、帶子等短部件，以小幅度和有限延遲跟隨身體；不得拖慢腳步接觸、遮住臉或讓物件浮離固定錨點。降低動態時可停用非必要的次級動態，仍顯示清楚站姿與必要互動動作。

## 三階段整套驗收

1. **範圍與姿勢規格**：列出四位角色各自必需的動作、方向、影格數與節奏，核對全身比例、身份特徵、服裝槽位、head／hand／feet 錨點與前後層規則。每個需求都要有素材計畫；空白格、重複格、同一個 NPC 圖集借給另一角色都算未完成。
2. **逐格美術與換裝檢查**：角色每種必要動作完整出圖，逐方向看循環順序、接觸腳、身體重量、臉與服裝輪廓；至少檢查各服裝槽位的替換組合、帽髮遮擋、前後手／道具及所有錨點。小尺寸實際遊戲視角需看得懂。未畫的影格不得以透明圖、靜止佔位格或生成裁切半身圖冒充。
3. **原生遊戲情境檢查**：逐角色演示站立待機、待機小動作、移動起停轉身、互動與專屬動作的進出循環；換裝前後逐段檢查人物完整、腳底落地、部件同步、碰撞／位置不漂移。每位 NPC 都要獨立完成其必需集合，暫停／恢復與降低動態狀態也要確認。只有四位角色全部通過才算「整套」；研究文件、資料檢查、單格截圖或部分角色素材都不代表整體完成。

目前仍只有主角八方向八格步態與 NPC 四格 routine 的能力基線；本文把更完整姿勢集、獨立待機、服裝逐格覆蓋與角色專屬動作列作需求，並未宣稱這些素材或原生驗收已完成。
