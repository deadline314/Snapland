# 全人物逐格來源的入庫門檻

2026-10-26 的兩份人類正面招呼候選使用同一張既有原圖，第二份再要求修正第一份固定格位。兩份皆為 image_gen.imagegen 透明輸出，六個完整人物、三欄兩列；原圖、完整提示詞、來源與指紋保留於 ART-17 證據。**兩份均拒收，未安裝至遊戲素材或播放清單。**

不能因有六個不同手勢就當作六格合格動畫。先用來源承諾的固定 512×512 格位檢查不應移動的實體部件；本次手臂有動作，身體相機卻應保持原位。以第一格相機鏡頭的明確 42×44 RGB 區塊匹配其他格，在有限搜尋帶逐列計算誤差，不用全輪廓／鞋底置中。兩份的相機 X 分別相差 43、42 個來源像素，且後排鏡頭 Y 上移約 6–7 像素；獨立透明輪廓底部也分別上移 7、6 像素。固定格位診斷圖已實際查看，足以拒收，不把這個診斷冒充正式動畫播放。

匹配誤差並非零：來源相機本身也被重新繪製。因此指標只用於指出明顯格位錯誤，不能證明相機或人物像素一致。手勢、完整四肢、角色比例、固定頭／根點與自然銜接仍須逐項審閱；禁止用每格透明外框／鞋底重新置中、單獨拉伸頭身、複製姿勢或淡化重影掩飾問題。若來源格位不符，回到原件修正，不能讓 runtime 猜測補償。

透明來源另要實際合成在淺底與深底看。檢視器中深色的透明 RGB 不是可見背景；先查 alpha 再判斷光暈，不因 alpha=0 的顏色拒收，也不能為了裁邊直接刪掉有用的弱 alpha 原畫。本次初步深底印象由 alpha 檢查及實際淺底合成修正，最終拒收理由是格位與人物不一致。

現有舊動作也不能不經檢查共用遮罩：舊互動是側斜視角、拍照相機／雙手遮臉；招呼、拍照與互動另有專用 front 動作來源。擴充舊原圖的方向映射時必須重新確認實際選中的來源，不能因改成 front 就意外用上另一張專用動作並冒用舊遮罩。ART-18 本輪只接入實際驗證的舊正面慶祝圖。
