# 阿浪八相位原畫複核（2026-11-17）

本輪為 ART-16 的來源研究，結論是**不接入正式角色**。二十份內建圖像工具輸出包含識別色導引、完整圖集與局部修正，不能算成二十套已批准動畫。最終候選有左右各八張可辨識近遠側的姿勢；Main 巡路仍暴露起停外觀與播放節奏問題。ART-16、ART-17 維持原驗收條件。

基準 `63ab519b22605d0774744d218cfc199e280bee44`；分支 `codex/animation-source-20261117`。正式 PNG、播放清單、巡路與所有舊動作沒有交付變更。

## 實際閱讀與採用範圍

本輪另核對四份第一手文字文件；前輪步態、逐格與骨架研究仍見 [動畫品質研究](animation-quality.md)。文件機制不代表本輪角色已自然連續播放。

| 第一手來源 | 觀察與本輪決定 |
|---|---|
| [Aseprite layers](https://aseprite.org/docs/layers/) | 圖層可有逐格內容，鎖定層可禁止繪製。採用固定部件與可動部件分開檢查；不以凍結整條上半身代替頭部一致。 |
| [Spine slots / draw order](https://esotericsoftware.com/spine-slots) | 顯示附件與繪製順序分開管理，順序可以逐格變更。據此檢查褲口、前後大腿與擺臂的遮擋，沒有引入骨架或重新拼腿。 |
| [Godot Image.blit_rect_mask](https://docs.godotengine.org/en/stable/classes/class_image.html#class-image-method-blit-rect-mask) | 遮罩 alpha 非零時複製來源像素，須維持對應尺寸。以二值頭部遮罩做離線比較，另外檢查遮罩外完整來源是否相同。 |
| [Unity Sprite Swap](https://docs.unity3d.com/Packages/com.unity.2d.animation@10.0/manual/SpriteSwapIntro.html) | 依分類與標籤選來源；互相衝突的 Sprite 與 Resolver 動畫會造成播放問題。沿用本專案單一完整姿勢來源的方向，不添加第二套人物驅動者。 |

## 原畫與固定根比較

識別色導引將近側整條袖、褲口、腿與鞋標成同色，再恢復衣物明暗。早期來源只交換手臂或鞋色，第二／六與第三／七格的褲口遮擋仍不清楚；獨立複核拒收後才修正。後續整張修圖也會意外重畫未指定部位，不能因提示要求「其餘不變」就視為像素相同。

最終左向第六格沿用具深色承重靴的完整原姿勢，只從另一份生成輸出擷取 `40×29` 的遠側大腿修色。重用既有 `source_repairs.apply_repairs`，原圖、局部圖與前後可見像素雜湊均綁定；頭、手與腳保護區不與修正區重疊。沒有重畫、旋轉或拉伸腿部，也沒有採用生成圖中其他改動。

整條水平標頭轉貼會截斷袖根，已拒收。最終比較使用帽、髮、臉與頸部的二值輪廓遮罩；肩與手臂在遮罩外繼續擺動。遮罩上的大片透明區不能證明語義正確，仍另看完整人物與肩頸接縫。本輪沒有將試驗遮罩當成新的正式驗收規格。

原生正規化先保留共同比例及每列共用地板。右向首列四格另用同一個來源地板值補償一像素取樣差；不是逐格追鞋底。Main 對照再發現初版右向整條圖集的身體偏右，依獨立目測的褲襠參考點把右向八格統一平移 `[-20,0]`；右向參考點落在 X=155–165，左向不移動。這是作者標注與整列／整向定位研究，**不是正式腰部影像對位檢查通過**。

透明區雜點使用現有 `clean_part` 流程處理：alpha<8 清除，其餘保留最大連通人物。每格移除約 1,300–2,100 個非零 alpha 像素，alpha≥128 的人物像素移除數全為零。原圖完整保留。

最終十六格的研究自檢結果：實際人物 alpha≥128 底部均為 448；同向遮罩內頭部相同；在明列的整向定位及已批准的局部修色之後，遮罩外來源改動數為零。此結果只涵蓋候選畫布，沒有取代正式頭部 ROI、腰部樣板、來源指紋或腳底測試，也沒有放寬原門檻。

## Main 原生結果與拒收理由

使用正式 Main 與既有原生巡路檢視入口，暫時替入候選並試驗步距 1.2，速度仍是 0.6。每次程序都用獨立絕對存檔路徑；結束後以 `finally` 還原三份被暫代的正式檔案。最後逐一與備份雜湊核對相同。

| 範圍 | 實測 |
|---|---|
| 定位修正前正常／慢速 | 各觀察左右十六張行走，以及兩側四張起步與四張收勢；正常 460 格，慢速／重建 1,842 格。 |
| 最終定位正常 | 460 格／30 FPS／15.333333 秒；左右十六張行走、起停與最後待機；exit 0、0 ERROR。 |
| 最終定位真實四分之一速度／重建 | 1,842 格／30 FPS／61.4 秒；time_scale=0.25，重建後再觀察巡路；exit 0、0 ERROR。 |
| 原地起步 | 最大根位置漂移 0；NPC 根與路線未由檢視器搬動。 |
| 四部 MP4 | 全段解碼通過；最終兩部指紋與交付影片相同。 |
| 原有來源回歸 | 素材清單建置與像素局部 Python 共 15 項通過；這不是候選自然度驗收。 |

正常影片的每秒四張診斷取樣已逐張查看，另查看慢速左右代表姿勢與起停圖。行走頭髮輪廓、頭身及衣物比例與既有起步／收勢來源仍有差異。另試驗步距下的理論切格率為 `0.6 / 1.2 × 8 = 4` 張／模擬秒，實際相鄰取樣也約每 0.25 秒換格；增加欄位數沒有證明改善輪播感。跨不同往返記錄的首次格位時間不能拿來當同一段步態的持續時間。

因此最終候選拒收，沒有替換正式來源或採用試驗步距。報告保留 `OBSERVATIONS_COMPLETE_VISUAL_PENDING`，技術 PASS 不轉成視覺 PASS。沒有宣稱真人連續觀看、試玩、試聽或即時性能；影片使用固定離線節拍及 Dummy 音訊。日誌保留既有材質遮擋警告及低磁碟空間警告，錄影正常結束。

試驗也保留了資料缺漏、過大透明裁切及找不到共同比例的失敗紀錄；其中退出碼 0 卻含 SCRIPT ERROR 的程序全部列為失敗。候選在來源與 Main 視覺階段已拒收，沒有以新的降低動態或 PCK 檢查冒充正式交付。
