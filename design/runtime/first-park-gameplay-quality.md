# 首區十二款小遊戲：玩法、操控與計分品質研究

狀態：設計研究稿（尚未實玩；不是遊戲驗收紀錄）
範圍：SG-16–SG-27、`game/data/welcome_games.json`、`game/minigames/session.gd`。只提出可驗收方案，不改程式、測試或收藏規則。

## 研究方式與參考

我讀了 SG-16–SG-27 的需求與驗收條件，逐項比對 welcome catalog 的目標、輸入、普通／惡魔條件，再讀 `session.gd` 的回合狀態、命中判定、分數更新、提示和結算。下面的程式觀察是靜態閱讀所得；沒有宣稱完成實玩或手感測量。外部參考均為開發商、發行商或規則出版者的一手頁面。它們提供可觀察的設計範例，不代表我取得內部設計資料或遊戲源碼。

## 目前共同問題與建議流程

`session.gd` 目前 1280×720 畫面把完整 controls、目標和 devil hint 長期放在兩條頂欄，遊戲提示另固定在底欄，另有分數與時間。`_feedback()` 約半秒淡出，回合結算回傳 `{game_id, success, devil, score, assisted}`，不含評分理由或各次事件。除氣球快遞外，絕大多數遊戲只有 60 秒正式時鐘；氣球有出發前練習。分數目前依遊戲分別加固定數字，但很多判定仍只有中／不中，分數不能解釋精準度。

建議每款遊戲在正式回合前提供同一套短流程，但用該款真實畫面教學：

1. **目標頁**：一張全局畫面標出成功條件、可操作物件和完成方向；文字最多兩句。
2. **輸入頁**：標註鍵盤與滑鼠等效操作，截圖畫出游標、方向、作用範圍；不使用只有顏色的指示。
3. **判定頁**：同一場景並排成功、普通命中與失誤截圖，指出命中線／範圍、得分差異和錯誤原因。
4. **練習頁**：固定且可重設的練習局，按一次只教一種技能；練習不消耗正式回合時間，按「正式開始」才重設狀態與啟動原有時限。

完整教學可從每款遊戲的「？」重看。正式遊玩時只留一個明確目標、當前階段／剩餘物件、可讀的判定標記和事件後回饋；移除常駐操作句與長加碼提示。成績記錄要保留事件數據與組成，結算顯示「分數由哪些實際行為得來」，不是另一句「完成得很好」。減少動態時仍以形狀、文字、位置和音效中的至少兩種表達關鍵訊號。

練習、教學、暫停和結果畫面不計時；不延長正式時長來補教學。所有普通拍貼仍依 catalog 的普通目標取得；惡魔拍貼仍依各款原本的精準挑戰取得。總分本身不代替任何拍貼門檻。單人即可玩完整十二款與收齊內容；不加入多人限定或隨機數才成立的成績深度。輔助模式可以放寬控制容差，但仍要讓玩家完成同一目標，不自動替玩家命中；回合結果要註明啟用輔助。

## 各款修訂方案

### SG-16 氣球快遞（`balloon_delivery`）

- **目標循環**：讀目前高度的風向與短期預告 → 以方向鍵／WASD 或滑鼠引導接近當前信箱 → 在圈外提早煞車 → 低速進圈並維持停靠 → 前往下一個信箱。海膽碰撞應打斷停靠並沿碰撞方向彈開，讓避險結果可見。
- **輸入反應**：保留加速、風力和煞車的不同慣性感，但鍵盤與滑鼠應同樣有可控的加速／停止曲線。風向箭頭、預告時間和實際受力必須呼叫同一套風場函數；畫面同時顯示「現在」與「預告」，不另外放教學長句。煞車需清楚顯示速度下降，不能讓煞車也切掉轉向。
- **命中／失誤**：現行每站需進 66px 半徑、低於 68px/s 並停留 0.5 秒；超速穿圈會記一次錯。建議把有效停靠圈與速度線畫在信箱附近，顯示短暫進度弧；圈外掠過不記失誤，只有進圈超速、信箱順序錯或海膽實碰才算失誤。保留 catalog 普通「限時依序送完三袋」和惡魔「三站零碰撞且穩定停靠」條件。
- **分數解釋**：每袋拆成「送達基分」和一次性「停靠品質」：依抵達瞬間速度、離中心偏差與穩定停留時間計分；海膽撞擊另列碰撞扣分。現行每站固定 +150 無法區分飛行技巧，應改為可看懂的明細；總分不更改普通／惡魔門檻。
- **教學截圖**：①起點標方向鍵、滑鼠導引與目的地；②風向表同時標現在及 0.8 秒後方向；③圈外煞車、速度降線與停靠進度；④海膽繞行路徑與成功停靠結果。
- **技術驗收／root 實玩**：固定相位重播下，預報向量要等於預定時間取樣的實際風；煞車前後速度連續且可預測；信箱各只計分一次。實玩需測鍵盤、滑鼠、低速靠站、逆風靠站與誤觸海膽；確認停靠延遲不是輸入延遲。

### SG-17 風箏穿環（`kite_rings`）

- **目標循環**：看下一環高度與風帶 → 提前調整風箏升降／迎風 → 以穩定姿態穿過環心 → 準備下一段。五個環的軌跡和障礙在出發時完整可見，環中心可用形狀和刻度標示。
- **輸入反應**：目前 x 以固定 118px/s 前進，y 每幀加控制量與微小正弦擾動，滑鼠則直接設定 y。改成統一的「目標高度」或「垂直加速度」模型：鍵盤持續輸入可重複產生同一變化，滑鼠指向高度也走相同加速度／限速，不能瞬移；風箏傾斜、線張力和尾帶方向要反映速度及側風。
- **命中／失誤**：現行到環的 x 位置只檢查一次 `abs(y-ring_y) <= 34`，漏掉風箏碰撞盒寬、高或環面前後的可讀性。依風箏中心穿過環平面的時間，檢查完整碰撞盒落在環孔內；以中心偏差分三級：中心穿過、擦邊但完整、安全外失敗。錯過不應再在畫面遠處追溯判定。
- **分數解釋**：每環按中心偏差、通過時速度與是否碰到環架給 0–200 連續／分級分；五環最高 1000，結算逐環列精準／擦邊／失誤。普通仍要求抵達終點並全穿過；惡魔要求五環中心命中、零擦撞。
- **教學截圖**：①完整五環路線與風向；②同一環的中心／擦邊碰撞盒；③鍵盤和滑鼠都把風箏導向同一目標高度；④環架擦撞後的單次結果。
- **技術驗收／root 實玩**：三種輸入在同一時間點能達相同位置容差；碰撞判定只發生一次且可從風箏碰撞盒重現。實玩需測快速連按、連續按住與快速滑鼠移動，確認無瞬移、抖動或不可見的風向加速。

### SG-18 噴泉跳拍（`fountain_timing`）

- **目標循環**：觀察水柱升高 → 在峰值前預備 → 水柱到達峰值／指定拍點時跳 → 看起跳與落地是否踩中同一視覺節奏。正式局共三次；目前週期 1.35 秒，命中窗只由時間決定。
- **輸入反應**：空白鍵和點擊均觸發同一跳躍事件。現行命中窗為 `0.86–1.12s`，畫面寫「最亮時」但窗口和峰值是否同相需以實玩錄影核對。讓水柱高度、節奏燈、起跳、空中頂點和落地使用同一個 beat timestamp；輸入必須在起跳當幀鎖存，不能讓點擊漏過更新順序。
- **命中／失誤**：用誤差相對拍點分「完美／準確／未中」，同一試次最多計一次；過早與過晚都在畫面標明偏差方向。普通照 catalog／票面要求三次成功，惡魔三次均完美且零失誤；目前 session 的 `count >= 2` 會讓兩次成功就通關，和既定普通門檻不一致，需在實作前對齊，不能把較低程式門檻當作正式要求。
- **分數解釋**：三次各按誤差給 0–300：例如 ±70ms 內 300、±160ms 內 180、超出為 0；最終顯示每次偏差毫秒數與平均偏差。不要像目前一樣只要落在窗內就固定 +100。
- **教學截圖**：①水柱低位、上升箭頭；②峰值、亮燈和預備節拍同步；③不同偏差的起跳時間線；④空中姿勢與落地拍點同一條時間尺。
- **技術驗收／root 實玩**：使用合成輸入在拍點 ±50/±100/±200ms 測出預期等級；鍵盤與點擊結果完全一致；暫停／恢復不讓 beat 相位跳躍。實玩需核對視覺峰值與聲音拍點在正常速度下是否真同步。

### SG-19 人潮指揮（`crowd_traffic`）

- **目標循環**：看目前號誌方向與等待隊伍目的地 → 在路口前切到安全相位 → 讓該隊通過 → 觀察隊伍消退、等待時間和下一組需求。畫面已有雙向通道和六組遊客，但目前六組僅按固定交替方向出現、2.2 秒一組；玩家通常只需交替按 Q／E。
- **輸入反應**：讓 Q/E 與點擊明確選「放行左向／放行右向」，兩者選中同一相位；有明確輸入鎖定／轉燈過渡，不能按鍵雖切到正確燈色但已無法影響隊伍的時刻。隊伍到達路口前預告目的地與倒數距離。
- **命中／失誤**：設計兩車道互斥相位。錯放不可只加一次抽象 mistakes；若衝突隊伍同時佔用斑馬線才判碰撞，若玩家延誤則隊伍排隊、等待值增加但仍可恢復。六個隊伍採固定可重播需求序列，至少有一段同向連續隊伍，讓保留相位有價值，不靠隨機車流。
- **分數解釋**：分數按安全通過人數、等待秒數和是否造成衝突拆項。每隊安全通過給基本值，依等待低於／高於可見目標線給效率分；碰撞不加分並列原因。普通是安全帶完六隊，惡魔是六隊全安全且無錯放；等待扣分不抹掉已取得普通資格。
- **教學截圖**：①路口、兩個方向箭頭、號誌目前相位；②不同顏色／形狀的隊伍目的地和預告；③切燈後安全放行；④衝突時的紅線與錯放結果、等待不是碰撞的例子。
- **技術驗收／root 實玩**：固定序列回放、訊號相位與碰撞時間一致；同一相位不會雙重放行；隊伍等待／衝突由事件記錄可重算。實玩需測快速連按、連續同向隊伍、切換前後一幀與無聲遊玩時的方向可辨性。

### SG-20 帽子救援（`hat_catching`）

- **目標循環**：看帽子落點與當前陣風 → 移動到落點下方 → 在接帽線接住 → 看連續救援紀錄並轉向下一帽。帽子目前以垂直速度落下，偶數帽有小幅正弦水平漂移，角色在 y>560 時僅按 x 間距是否小於 65px 判定，缺少手部接觸與風的對應。
- **輸入反應**：←/→ 與滑鼠 x 指向同一攔截位置，統一以可調加速度和最高速度到位；滑鼠不可瞬移。風向旗／粒子應在帽子路徑上預告位移；「捕捉線」固定在角色手掌高度，而非帽子進入 y>560 的任意時刻。角色伸手動畫與聲音落在接觸幀。
- **命中／失誤**：以帽簷落點與角色可接範圍重疊判定，中心接帽和邊緣擦帽分級；沒重疊才算漏接。6 帽依序一次計分；過早或過晚移動不扣分，避免把等待當錯誤。普通接住至少四頂、惡魔六頂全接。
- **分數解釋**：每帽中心命中 120、有效邊緣接住 70、漏接 0；連續中心命中增加小型 streak 品質分且漏接時歸零。結算列六頂逐帽位置偏差、風向和救援率，不能只顯示固定 +100。
- **教學截圖**：①人物左右活動範圍與接帽線；②帽子目前風向、預測落點；③中心接帽與邊緣接帽對照；④未接到的落點與漏接標記。
- **技術驗收／root 實玩**：帽子離散時間步和角色接觸線一致；每頂帽恰好結算一次；鍵鼠同軌跡可重播。實玩需測同時來帽、兩側邊界與最後一刻換向，確保不是必須預知隱藏軌跡。

### SG-21 彩帶節拍（`ribbon_rhythm`）

- **目標循環**：短 count-in → 看舞者／聽音樂示範一個動作 → 依八拍短句輸入左、右、跳 → 結算逐拍準確率。現況有固定 8 動作序列，但每拍 0.82 秒，命中窗只從拍點起算前 0.12 秒，沒有精準／合格分級；在拍點後才按即失誤。
- **輸入反應**：左／右／空白鍵和畫面左右半側／中心區對應相同動作；每拍之前出現方向符號或舞者動作預備，音樂強拍、動作命中時刻和評分時間戳共用 chart。節拍用可設定校準偏移，但不降低錯拍懲罰。練習段不計正式時間。
- **命中／失誤**：把當拍誤差置中（例如 ±70ms perfect、±150ms good，外為 miss），早／晚的視覺位置不同，錯動作與錯時分開說明。錯拍仍消耗該拍，維持樂句完成；普通六拍以上命中（輔助可保持票券既有門檻）、惡魔八拍無失誤。
- **分數解釋**：八拍每拍依 timing grade 給 100／60／0，另以連續 streak 只給小額上限加分。結算提供 perfect/good/miss、平均絕對時間差與最高連段；不要每個成功都同樣 +75。
- **教學截圖**：①count-in 與第一拍；②左／右／跳三種舞者預備姿勢；③提前／準拍／落後時間線；④一個錯拍後仍繼續完成句子的結果。
- **技術驗收／root 實玩**：在 60Hz、常見音訊延遲和降低動態設定測 beat timestamp；keyboard/click 的相同事件誤差應得相同級別；暫停或失焦時歌曲與拍點一起停。實玩需校對音訊輸出延遲與實際聽感，不只看模擬輸入。

### SG-22 花壇水路（`flower_pipes`）

- **目標循環**：從固定泉口追蹤管路 → 找出第一個斷點／方向錯誤 → 旋轉直管或彎管 → 觀察水實際流到哪些花槽 → 接通排水口。現況棋盤是 4×4，點擊或游標選格後空白鍵旋轉；BFS 依 reciprocal connection 判斷出口，但繪圖的 `flowing` 集合是硬編碼，不隨實際連通改變。
- **輸入反應**：滑鼠點格與方向鍵移動游標再按空白，都只旋轉一次 90°，選中格高亮、旋轉後即重算連通。水流從泉口沿互相接上的管段一格格推進，已連通的花朵才開；轉回斷點時水停止並保留原因標記。
- **命中／失誤**：只有泉口到排水口透過相鄰互通端點形成完整路徑才完成。死端不算錯誤，只是當前無水；每轉一次是步數，不是失誤。可顯示已經流到的最遠節點，但不畫未連通格的假水流。
- **分數解釋**：用固定牌面可計算的最短解步數 `par` 做基準。完成得分可用 `1000 − 40×max(0, moves−par)`（下限 0），並列解答步數與實際步數；惡魔仍採 catalog「四轉或更少」，普通仍是連通成功。若實際固定牌面的 par 不等於 4，先修牌面或調整該數字，再鎖驗收；不要因任意旋轉都扣 20 分就稱為有效評分。
- **教學截圖**：①來源、出口與方向端點；②一個彎管旋轉前後的互通端點；③第一段真實水流與第一個斷點；④解通、步數與 par 對照。
- **技術驗收／root 實玩**：繪製流路與 BFS 共用同一函式；固定初盤可重複解且最短步數經獨立 BFS 驗算；鍵鼠選格旋轉相同。實玩需確認旋轉前後的水流回饋足夠清楚、4 步惡魔門檻確有合理解。

### SG-23 招牌平衡（`sign_balance`）

- **目標循環**：觀察招牌偏向／風向 → 用左右控制修正重心 → 在每個拍點讀當下安全帶 → 將招牌維持在中心並準備下個陣風。現況正弦風每秒作用於 balance，方向鍵持續修正、點擊左右各加減 0.16；安全帶之外記一次 mistake 並把 balance 拉回 0.72。
- **輸入反應**：招牌視覺角度、中央支點、下方儀表必須由同一個 balance 值映射；風箭頭顯示符號和當前力矩，預告短期轉向。點擊左／右與方向鍵同作用，不瞬間把牌拉回安全區；設輸入 dead zone，避免放手後漂移。
- **命中／失誤**：每個節拍只評一次。現行安全門檻普通 `|balance|<0.25`，精準 `<0.12`；顯示兩條真正對應此門檻的線。安全帶外過線才記一次風險，重複停在外面不能每幀連續加 mistake；到三次失衡結束的規則可保留。
- **分數解釋**：七拍每拍中心 100、可控安全帶 60、帶外 0；另列發生的過線次數。700 滿分直接代表七次精準平衡；普通仍七次安全，惡魔為無過線且七拍精準。
- **教學截圖**：①支點、重物與重心；②風向造成的偏移與箭頭；③鍵盤連續修正／點擊單步修正如何映射同一儀表；④安全線和拍點評分範例。
- **技術驗收／root 實玩**：以畫面角度反推 balance 與儀表值一致；一次過線只計一次；七個節拍 timestamp 不受幀率影響。實玩需測不同按鍵保持長度、連續點擊、陣風逆轉前後的可控性。

### SG-24 影子捉迷藏（`shadow_alignment`）

- **目標循環**：沿影子與牆上輪廓觀察偏差 → 移動燈源 → 讓整個影子而不是中心點進入目標 → 維持三秒 → 看平均對準品質。現況 alignment 是一維 x 值；遮罩與目標同形狀，只靠平移；游標 x 映射位置，鍵盤每次移 0.04。
- **輸入反應**：滑鼠拖曳和 ←/→ 改變同一盞燈位置；畫面即時顯示燈源、投影方向、影子輪廓與目標輪廓。顯示當前偏差方向與距離，不用額外常駐操作句。鍵盤每步應小到可以落在中央精準帶。
- **命中／失誤**：用影子與目標輪廓的像素／幾何重疊率判定，並要求輪廓中心距也在門檻內；目前只比較 `abs(alignment-target)`，最多 ±0.065，不能代表整個影子都貼合。超出後連續時間歸零；按下滑鼠但尚未開始計時不應加 mistake（目前偏離 >0.3 的每次點擊都加錯）。
- **分數解釋**：連續三秒按每秒輪廓重疊率積分，最後按平均重疊與最大偏心給 0–300；結算列平均重疊、最長連續穩定時間。普通是對準維持三秒，惡魔要求首次對準後連續維持三秒。
- **教學截圖**：①燈源、人物、牆面投影的幾何；②左偏／右偏如何拖燈修正；③輪廓中心吻合與一處角落未吻合對照；④三秒計時的累積與中斷歸零。
- **技術驗收／root 實玩**：投影模型和目標使用同一場景變換；以可測重疊率驗證結果；每次失敗有一條錯誤事件。實玩需測拖動靈敏度、鍵盤小步長、動態降低時仍能讀到輪廓偏差。

### SG-25 泡泡合照（`bubble_photo`）

- **目標循環**：拖動瞄準泡泡位置 → 發射泡泡並看它擴張／漂移 → 等吉祥物完整進框與快門窗 → 拍攝 → 看該張完整度、置中和快門品質。現況有三次拍攝循環，泡泡中心與第二次點擊位置各自接受一組容差；`bubble_perfect` 再以更緊的位置與 phase 規則決定惡魔。
- **輸入反應**：清楚拆出「瞄準／吹泡泡」和「快門」兩種狀態。滑鼠游標影響瞄準；空白鍵應把當前游標／預設引導位置作為一致的瞄準點，不能像目前一樣固定設成 `(790,target.y)`。發射後泡泡的大小與相框一致，快門可鍵盤或點擊吉祥物觸發。
- **命中／失誤**：必須同時滿足：完整 mascot 包在可見泡泡內、快門框包含完整 mascot、快門時間落在顯示的有效窗。邊緣截斷／只框到泡泡但沒包住吉祥物不算成功。每週期最多一張結果，錯誤分「泡泡未包住」「出框」「快門早／晚」。
- **分數解釋**：三張各自 0–100：完整入框 40、中心構圖 0–30、快門準度 0–30；依實際邊界／中心誤差計算。普通兩張有效照，惡魔三張均完整且高品質置中。結算顯示縮圖框、裁切完整度與中心偏差；不只 +100。
- **教學截圖**：①游標決定發射方向／中心；②泡泡擴張且目標在框內；③快門窗亮起後拍照；④完整置中與切到耳朵／尾巴的照片比較。
- **技術驗收／root 實玩**：以同一 mascot hitbox 判泡泡、相框和結算縮圖；校準不同 viewport 上的滑鼠座標；三個週期各只登錄一張。實玩需測鍵盤、滑鼠、吉祥物上下極值和邊緣裁切，確定視覺相框就是真正命中框。

### SG-26 長椅換位（`bench_swap`）

- **目標循環**：辨識兩組好友徽章 → 看四個座位的鄰接分區 → 選兩座交換 → 觀察隊伍分組是否更接近目標 → 完成時回看最少步數。現況初始 perm `[2,0,3,1]`，鍵盤按 1–4 或滑鼠兩次選座交換；但勝利檢查要求精確排列 `[0,1,2,3]`，catalog 普通要求的則是「兩組好友坐在一起」，兩者判定不一致。
- **輸入反應**：點選第一座時明顯高亮並提示下一選擇；第二次選取即交換，按 Escape 或再點同一座取消。鍵盤按數字、滑鼠座位命中完全一致，選中後的動作動畫與交換邏輯同一 tick。
- **命中／失誤**：以徽章配對為規則，驗證好友是否坐在被標記的相鄰雙座區；只要合法分組就可普通完成，不要求好友各自坐回個人編號。若遊戲本意其實要四人回指定座位，必須將 catalog 和教學改成「回到姓名牌座位」，不能文案說朋友坐一起卻檢查 exact permutation。建議保留固定初盤、為初盤算 par，惡魔沿用三次內完成。
- **分數解釋**：顯示完成所用交換數、固定初盤的最短解 `par`、多出的交換。例：`分數 = max(0, 500−50×(moves−par))`，完成 par 解始終 500，過度操作才扣；也可記錄「無冗餘交換」徽章。不得按點擊次數與解題品質混為一談。
- **教學截圖**：①四個座位編號、好友徽章與成對座位框；②選中一席再選第二席的交換動作；③兩組好友坐在各自雙席；④最短解步數與實際步數。
- **技術驗收／root 實玩**：桌面提示、catalog goal、solved predicate 和教學使用同一套 `groups_are_adjacent`（或明確座位目標）；固定局面經 BFS／窮舉確認 par。實玩需測同座取消、鍵鼠混用、完成即時性與大螢幕點擊區精度。

### SG-27 迎賓大合奏（`melody_memory`）

- **目標循環**：聽／看一段迎賓樂句 → 等示範結束 → 按相同花朵順序回奏 → 成功後加入新音符、組成更長樂句 → 三段結束後聽完整收尾。現況每輪長度為 3、4、5，序列在新局隨機生成；答錯後重播原句，正確音符 +25、完成段落 +100。
- **輸入反應**：1–4 與四朵花點擊同一音符，音符亮燈、音高和 `note_played` 共用 index；播放與玩家回奏採不同音色／伴奏層，讓狀態一耳可辨。序列顯示完才接受輸入；音符節奏按固定間隔，失焦／暫停時播放同步暫停。
- **命中／失誤**：正確音符立即確認，錯誤時說出「第幾音錯」並重播完整序列；以獨立小節線分清已記錄到第幾音。固定旋律採可記、可唱的樂句（如第一句短 motif、後兩段逐步追加），不要用隨機不同序列假裝深度；每個正式 run 可保留有限且標明的曲目變體，不依賴 RNG 影響難度。
- **分數解釋**：正確音符 +25、完成小節 +100；錯誤音符不加分但允許重聽再試，錯誤數會顯示於結算。普通保持三段完成、惡魔三段零錯；分數拆「輸入正確音符、段落完成、錯音數」。現有計分的三段完美分數上限是 600（12 音符×25 + 3×100）；顯示上限與分項，避免玩家不知道段落獎勵來自何處。
- **教學截圖**：①四花朵與鍵盤 1–4 對照；②示範時唯一亮燈和音高標記；③回奏進度 2/4；④追加一音後新舊樂句對照與收尾。
- **技術驗收／root 實玩**：音訊事件、燈號和按鍵接受窗口用同一音符時間戳；暫停／降低動態不漏音；固定樂句可從 seed-independent fixture 重播；每一音最多計一次。實玩需盲測聽覺／視覺辨識、鍵盤與點擊節奏、錯音重播不煩躁程度。

## 整體驗收建議

- 十二款每款都錄一段正常速度首次遊玩流程：進入圖解、重看教學、非計時練習、正式局、重試、離開；影片可清楚聽到節奏，截圖須在遊戲內原生畫面擷取。
- 每款提供可重播固定測試狀態：每個分數邊界兩側、每種失誤、輔助容差、降低動態、鍵盤與滑鼠等價輸入。用事件帳本重算最終分數和收藏資格。
- 對每款至少找一位沒玩過的人只看截圖教學再操作；記錄首次誤解點並修教學，不將靜態閱讀當成手感驗收。
- 根據實玩校準輸入延遲、判定窗和手把／鍵鼠差異。技術自動測試證明規則一致，不替代 root 實際玩正常與輔助模式。
- 成功結算同時列普通資格、惡魔資格、分數明細和輔助狀態；未達惡魔仍可取得已達成的普通內容。不得因教學畫面、暫停或重試造成回合時間流失，也不得以完成設計研究或截圖宣稱完成遊戲實玩。
