# [MAIN-23] 修正跨平台驗證差異

> 狀態：完成

## 內文

### 需求
同一份來源資料在 Windows 與 CI 的驗證結果一致，避免系統文字編碼、路徑分隔符或文字換行產生假失敗，同時保留真正缺件與內容變更的檢查。

### 來源
2026-11-11（Asia/Taipei）使用者要求持續逐票交付、維持穩定與容錯；本機完整檢查發現 Windows 與 CI 的驗證差異。

### 驗收條件
- [x] 衣物資料可在 Windows 預設非 UTF-8 環境正確讀取，原有缺件驗證仍有效。
- [x] 資源封裝檢查在不同系統的路徑表示下核對相同檔案與內容。
- [x] 步幅來源的 LF／CRLF 文字換行得到同一指紋，實際文字變更仍能偵測；步幅量測值保持相同。
- [x] 相關局部與完整 Python 檢查通過，保留原始失敗及修正後結果。

### 測試流程
1. 使用 Windows 本機執行完整 Python 檢查，核對原始失敗。
2. 檢查兩種換行、實際內容變更及原來的資源／衣物反例。
3. 重跑完整檢查，確認沒有放寬缺件、內容或量測斷言。

# Commit-1

## 內文

相同檔案在 Windows 使用反斜線路徑與 CP950 預設文字編碼，原驗證因此產生假失敗；文字檔換行也讓未修改的步幅資料看似過期。現在明確使用 UTF-8、以相同資源路徑核對封裝檔案，並讓文字來源指紋忽略 LF／CRLF 差異。原圖、步幅量測、封裝內容與缺件檢查保持相同。

新增兩種換行與實際內容變更的反例；原存的來源指紋可直接保留，不需重寫量測。原來的檔案位元內容、缺件與量測斷言均保留。

|---|---|
| 原始完整檢查 | 153 項，4 失敗與 1 類別初始化錯誤；原始日誌保留 |
