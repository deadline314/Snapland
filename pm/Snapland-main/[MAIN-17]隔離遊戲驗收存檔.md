# [MAIN-17] 隔離遊戲驗收存檔

> 狀態：完成

## 內文

### 需求

遊戲測試與原生驗收在啟動前指定獨立存檔；漏設或指向玩家預設存檔時立即拒絕執行，避免測試重設或遷移玩家進度。正常遊戲使用預設存檔的流程維持可用。

### 來源

2026-10-13 島上動畫驗收發現補充測試漏設隔離路徑，預設本機存檔及輪替備份已變成測試資料；原本內容未取得，沒有可驗證的原始復原副本。依使用者穩定、隔離及不破壞既有功能的規範補票。2026-10-16 CI 發現隔離驗收依賴 Windows 專用路徑資訊，Linux 尚未通過；沿用本票完成跨平台驗收。

### 驗收條件

- [x] 測試或原生驗收入口未指定獨立絕對存檔路徑時，在讀取、遷移或寫入預設玩家存檔之前拒絕執行，顯示具體原因及非零結果。
- [x] 指向預設玩家存檔的測試覆寫同樣被拒絕；原檔與備份的內容保持不變。
- [x] 明確使用独立路徑的局部測試正常執行；一般遊戲仍能正常載入、保存與恢復存檔。
- [x] 保存拒絕案例、有效隔離案例與局部驗證摘要，確認未把其他測試存檔冒充玩家原始存檔。

- [x] Windows 與 Linux 的隔離驗收均不依賴另一平台的環境變數，拒絕案例及普通假存檔往返都正常完成。

### 測試流程

1. 使用可丟棄的獨立預設存檔位置與已知內容，記錄原檔及備份的雜湊。
2. 以缺少覆寫、相對路徑及指向預設存檔三種方式啟動測試，確認拒絕且原始資料未變。
3. 指定獨立絕對路徑執行相關測試，並確認一般載入與保存正常。

# Commit-1

### 問題

一次補充驗收漏設獨立存檔，當時的本機預設進度與輪替備份已被測試資料覆寫。原本玩家進度沒有已驗證的復原副本，不能拿其他驗收存檔代替。

### 改動

測試與原生驗收現在必須先指定獨立、絕對的檔案路徑；缺少路徑、相對路徑、虛擬路徑及預設存檔目錄均在載入之前拒絕。正常遊戲保留原有載入與存檔流程。

### 驗收

Root 從這次提交的暫存內容重建獨立專案，實際執行拒絕案例與普通啟動子程序。拒絕案例前後三個已知假存檔的內容雜湊不變；普通啟動在唯一的假使用者目錄載入已知進度、保存新值，再由全新程序重開取得同一新值。原本 Snapland 預設檔案在本次驗收前後雜湊未變。本驗收是存檔流程檢查，沒有聲稱遊戲畫面或真人試玩通過。

### 測試結果與證據

提交內容的匯入、存檔隔離與核心流程 3/3 通過，0 ERROR。保留負面案例沒有改動資料的標記、兩次普通啟動的成功標記與局部測試結果：[隔離驗收紀錄](images/MAIN-17-isolation-validation.log)、[核心流程紀錄](images/MAIN-17-core-validation.log)、[事故後檔案核對](images/MAIN-17-live-profile-preservation.json)。完整套件交由 CI。

分支：`feature/island-experience`；遠端提交連結於提交後補記。票況：進行中。

# Commit-2

### 問題

Linux 的隔離驗收依賴 Windows 暫存與使用者目錄資訊，啟動時失敗並逾時；完整驗收也仍在等待舊版成功訊息。

### 改動

假存檔現在建立於已明確隔離的測試位置旁，依引擎實際提供的平台目錄確認唯一假使用者資料夾。每次拒絕後仍核對三個假存檔的雜湊，一般遊戲載入、保存及全新程序重開也只使用該假資料夾。

### 驗收

Windows 正常環境與移除 Windows 暫存變數兩組原生檢查均通過，0 ERROR，拒絕案例三個檔案雜湊均保持不變，一般假存檔載入／保存／重開成功。Linux 結果以這次修正後的 CI 為準；本票維持進行中。
