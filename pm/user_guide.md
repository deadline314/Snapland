## 1. 當前優先順序與完成標準

1. **先雕琢島上的實際體驗**，把主區域與第一園區做成能作為後續園區標準的完整體驗。先修主角／NPC 動畫、真正的 HD-2D、探索與設施、對話和整套 UIUX，不急著擴張更多簡陋內容。
2. 從主角上島開始；未來另做船上世界觀序章，現在保留前接點。主區域與第一園區需要完整可玩，其他園區先有清楚且有特色的路口。
3. 可集中處理多張相關票，逐票驗證與交付；品質優先於速度。不要停在研究、生成素材、單張截圖或半完成展示。使用者已授權自主做常規設計判斷，不需要反覆詢問是否繼續；遇到實質歧義或不可逆操作再澄清。
4. 精品指的是畫面、操作、目標、地圖、角色、故事、音樂與音效共同成立。細節要有主次、留白與辨識度，不能用雜亂、特效或大量文字掩蓋空洞設計。
5. 新的試玩回饋優先於舊的「已看過／通過」。使用者再次指出怪異、簡陋或不好用時，要重新找原因，不能沿用舊驗收結論。
6. **保留原本 2D 畫風，先完成主角部件樣本**：2026-10-16 使用者否定新製作的 3D 人物；要的是完整光頭人物底圖，再生成同風格的八方向頭髮與配件，綁定正確錨點並共享動作／方向／影格。先驗證換髮、帽、不同衣物、相機及行走起停轉身的正常與慢放，再擴其他角色。[ART-29](Snapland-art/[ART-29]製作主角完整換裝動作樣本.md) 已交付獨立 2D 主角樣本及正常／慢放檢視；正式島嶼後續已由 ART-31／32 修正定位與待機，ART-33／34 接入三款人類髮型動態。不同衣物輪廓與 NPC 仍依 ART-18／17 接續，3D 候選已停止、未採用。[最新管線決策](../design/runtime/character-production-pipeline-v2.md)。

- 角色逐格裁切後必須保留同一人物基準與固定畫布；不可用每格鞋底或透明外框重新置中。2026-10-16 使用者再次指出頭髮／身體與八方行走有中心漂移；要先校正全身圖格，再驗證髮帽錨點及正常／慢放，數值通過不等於視覺通過。

- 2026-10-16 使用者批准主角單款髮型的 2D 骨架樣本，並澄清主要問題是人走路時頭部有像素級位移、頭髮卻未跟隨。固定身體基準與每格頭部附件點必須分開；髮根要隨當格頭部，只有髮尾可回擺。[ART-30](Snapland-art/[ART-30]製作主角髮尾骨架動態樣本.md) 已完成微風短髮限定樣本、正常／四分之一速度分段檢視、八方向戴帽與無帽、起停轉身和暫停恢復。保留原 2D 原畫；當次是限定樣本，後續 ART-33／34 已將三款人類髮型接入正式島嶼。NPC 與其他種族仍使用完整原人物。

- 2026-10-16 最新回歸 [ART-31](Snapland-art/[ART-31]修正全部二維行走像素偏移.md)：使用者指出所有 2D 走路仍有偏移後，重新驗證正式島嶼及獨立樣本。已取消每格鞋底置中，採固定方向畫布、穩定頭頸來源與共用髮帽基準；600 格／76 組逐格比較、19 項 Python、13 組原生局部測試、八向戴帽／無帽共 16 組 GPU，以及正常／真實四分之一速度錄影通過。ART-31 當次採同向穩定停步；後續 ART-32 已接回固定頭頸的專用待機與眨眼，ART-33／34 已接入三款人類髮型動態。這些後續驗收取代「待機尚未接回、骨架僅獨立樣本」的舊狀態。這是本次局部接受，不是使用者試玩或全島驗收。

## 2. 島嶼與探索：真的在遊樂園玩

- 地圖需要有探索慾望、清楚地標、有意義的動線、主線／支線／角色與可發現內容，不能只把小遊戲入口機械式排成一列。
- 2026-10-20 最新要求：遊戲內容、美術及 3D 場景模型要更豐富，地圖要擴大，改善一眼望到底的感覺。擴圖須有可玩的路線、地標、前中後景和回程；不能只放大空地或把同款布景排得更多。這項 3D 要求適用場景，不撤回已批准的 2D 角色原畫路線。
- 加入有島嶼特色、玩家能親自玩的遊樂設施、休閒活動與拍貼，讓移動和停留本身有樂趣。
- 2026-10-20 最新補充：每張地圖都要有生動、可融入的世界活動，不能只走到地點、玩小遊戲和拿拍貼。可直接操作物件、自由控制方向／節奏、看到環境回應，且能隨時離開；先完成已開放地圖，未開放區域不得冒稱已建成。海岸自由互動以 MAIN-21 追蹤。
- 攤位依玩法有自己的造型、空間和接近方式；開始介面簡潔直接，不把每個攤位做成同款複雜面板。
- 使用者指定參考**《炸彈超人樂園3》**的園區、設施、人物與探索組合。研究實際設計方法，不能只寫名稱或照抄配置。
- NPC 放在容易辨識且不被建築擋住的地方。所有出現的角色都可用正常對話框交談，先以節制的滴滴聲配合逐字文字。

## 3. 美術方向：高精緻像素 HD-2D、有自己的性格

- 遊園是**細緻像素角色結合立體環境、完整光影、遮擋與動態的 HD-2D**；不是簡陋像素放大、平面背景貼圖，或加景深／泛光就算完成。
- 避免通用 AI 插畫感，尤其角色缺乏個性、背景過度華麗卻沒有可玩的空間，以及材質、透視、細節密度不一致。
- 角色要有可辨識的臉、比例、髮束、輪廓、性格和專用動作。世界需要自己的特色，不能把某位作者或單一作品的設計擬合成整個遊戲。
- 生成前研究提示詞與製作方法，明確限制比例、色盤、材質、構圖、動作與身份細節。生成工具、提示詞、來源圖及雜湊需可追溯；不合格就修正／拒收，不能只靠描述詞聲稱精品。
- 指定的四格海港／廣場／夕陽舞台／月夜背景曾被指出「太 AI」，需要重新處理像素語言與場景合理性，歷史修圖保留在 ART-19；現行十二款已改用 ART-5 專用場景，ART-19 已封存由 ART-5 取代，時段與降低動態依 ART-21 的現行矩陣。
- 「潮汐紙劇場」、青綠／珊瑚色與木銅海港是先前實作方案，不是使用者要求永久鎖定的材質或 UI 模板；使用者已明確否定舊紙卡式 UI，不能藉風格名稱把它恢復。

## 4. 動畫：整個角色自然、完整、一致

- 主角與每位 NPC 都要有自己的專用站姿、呼吸／眨眼、待機小動作、行走起停／轉向、招呼、互動、情緒與符合個性的專用動作。先完整做好主角、票票、小角、阿浪。
- NPC 可以服務、拿盤子、巡走、跳舞等；動作和停留節奏因人而異，不要全場同步、永遠招手，或把不斷表演當自然生活感。
- 步行需要自然重心、兩步交替、起停與轉向；主角採八方向並增加真正有意義的姿勢，NPC 依實際活動製作完整方向覆蓋。不能用重複幀、插值重影、像素差異或幀數宣稱自然。
- **已有八方向走路圖時，直接播放對應走路影格。** 不再讓額外程序步態蓋過原圖，不用拆腿拼裝、整身伸縮或扭曲角色來補動作；已被否定的膝蓋接縫、鞋子旋轉和比例不自然試作不能復用。
- 停止移動要有合適站姿與待機。缺少方向待機或正式行走素材，就明確記錄缺口；不能拿單張走姿、舞蹈或別人的動作充數。 主角八方向有專用待機來源：正面八格，其餘七向各四格；ART-32 已將固定頭頸的專用待機／眨眼接回正式播放。票票／小角正式行走仍缺。局部交付與原生審閱以 ART-17 紀錄為準。
- 招手、拍照與互動必須依實際來源影格和播放速度完整結束，不以固定短秒數提早截斷。背向時缺素材不能凍結在上一張走路圖。
- 保持跨方向／跨幀身份：頭身、臉、髮束、服裝、相機、包袋、手腳與道具不突然改變、漂離或分開。主角曾出現身體與頭髮分離，需列為固定回歸案例。
- 每幀頭、手、腳、鞋底、角與尾巴都完整；來源裁切、圖集跨格、鏡頭裁切、地板穿透及建築／其他角色遮擋要分開查。不能只靠腳錨數值或平均身高判定完整。
- 正常速度、四分之一慢放、逐姿勢全身圖都要**實際看過**，再檢查降低動態、場景重入及打包版本。影片和截圖放票裡；來源／數值檢查不能替代自然度審查。

## 5. 紙娃娃與外觀自由

- 玩家可購買、收藏與自訂衣服、帽子等；**膚色、種族、性別與基礎外觀可免費無限次更換**。衣物不鎖性別，試穿先預覽，再確認購買／穿戴。
- 衣服、頭髮、帽子和配件可分層，但共享同一動作進度、方向與影格，依姿勢調整前後遮擋、手／相機／背包及髮帽錨點。
- 不同衣服最終要有不同輪廓，不是全部只換外套顏色。部分動作才有的服裝候選不可混入正式衣櫃，造成同一件外套突然變背心。
- 髮尾、衣襬、背帶的次要動態需有合理幅度、延遲及固定點，不能拉壞臉、手、鞋、硬帽和相機，或再次讓頭髮與身體分離。
- 逐衣物、髮型、方向、動作與影格核對覆蓋；來源快照在合成前保存，不能拿可能已被改過的結果當原始基準。缺資源需記錄具體位置並安全顯示完整角色。
- 遊戲內離線衣櫃／收藏與 Steam 可交易經濟分開；不能把離線資料當平台已確認資產。

- 製作不同輪廓衣物時優先保存完整批准人物，只讓純衣料依明確肩／肘／腕及圖層順序隨動；不能因生成長衣而接受改臉、改手、改腳的整個新人物。保存合成前原格指紋、前景所有權及拒收稿；最後一格失敗也不能發布前面已完成的部分。
- 覆蓋同時核對原畫表與實際動作入口。未登記原畫的整個動作可能仍有回退路線，須另外列為渲染請求，不能湊作新原畫；新衣預覽不會因局部檢查通過自動進衣櫃。正常／慢放製作視窗須標明它與正式走路時序的差別，並以實際 1px 錯位反例檢查量測是否有效。[可重現流程與證據界線](../design/runtime/outfit-completeness.md)。

- 不同完整身體共用固定頭時，先逐像素證明原髮相同，才可共用既有頭髮保護；仍核對每格整身指紋。來源與目標的關節都要實際畫出檢查，袖片不能取到相鄰衣身；前景草稿也不能把褲子誤當手部而透進長衣。數值通過的版本仍需逐姿勢審圖，拒收稿保留。[可重現反例與多來源聯集](../design/runtime/outfit-completeness.md)。

- 原畫有多手或道具錯誤時先修來源，再製作衣物。固定人物畫布與保護區，只接受可重播、來源／修正片指紋明確的局部修正；不可用新衣遮住錯誤或替換整個生成的人物。整格指紋改變時，重新核對頭部所有權及所有髮型身體聯集，即使沒有改頭也不能沿用舊依賴。[來源重建、原生與打包分開驗證](../design/runtime/source-art-repairs.md)。

## 6. 環境動態、遮擋、日夜與光影

- 背景物件、建築細部與服飾依材質和用途呈現合理效果：海水、旗幟、植物、燈、布料等有各自節奏。追求有生命的環境，**不是每件剛性建築都亂晃**；統一管理並控制效能。
- 主角被建築擋住時，以足夠大的圓形透視保留辨識，可比較柔和邊緣等效果；不能因透視把角色腳底／輪廓吃掉。NPC 優先以站位解決遮擋。
- 光影要與實際光源位置、方向相互作用。日光、燈與角色影子須合理對應，不能互相矛盾或只有固定假影。
- 玩家可隨時切到凌晨、中午、傍晚、晚上；融入時段拍貼、任務與收藏等機制，不只換濾色。
- 小遊戲可依時段有合適光影與背景。靜態四時段圖不等於日夜整套遊玩都驗收完成。

## 7. UIUX、字體、對話與教學

- 2026-10-20 最新補充：整體 UIUX 減負；不以疊更多裝飾、卡框和常駐文字掩飾簡陋。畫面豐富且有風格，同時合理使用版面；長內容可用 Tab／分頁，確實需要捲動時保持單一、清楚且有設計的區域。
- **全遊戲重新審閱**：HUD、暫停、設定、旅券、收藏、拍貼、衣櫃、教學、小遊戲開場／目標／分數／結算都在範圍內，不只美化一個面板。
- 高精緻像素 UI；可採 3D 或偽 3D 的厚度、高光、投影與克制動效，保有清楚的焦點、按下、選取、停用等狀態，不要死板按鈕或浮誇雜亂。
- 充分使用可用畫面，主要操作一次看見；**一般頁面盡量免捲動**。長內容優先分類／分頁，真的必要才有單一合理捲動區；不要小窗塞大卡、巢狀捲動、文字重疊或裁切。
- 對話就用熟悉的對話框、說話者與繼續／結束控制，不做複雜入口。拍貼與其他操作需符合玩家習慣。
- 少放常駐長提示與混亂教學字串。做完整、可略過及重看的教學，包含**實際遊戲截圖**；必要 Hover／操作提示一句講重點。
- 使用合適且清楚的像素字體，並有多語系框架：缺字後備、長句、變數語序、文字方向、按鈕寬度及語系切換都要考慮；不能把框架當全作翻譯已完成。
- 3D提示可能被2D介面底板蓋住；visible、旋轉與投影數值都通過仍可能看不見。以同資料的舊／新版原生畫面和實際像素反例核對，必要資訊放在正確的前景層；不要只讓節點測試通過。
- UI 實看要核對真正可見的文字、行數與內容，不只檢查容器矩形或估算字高。地圖／圖上的控制須檢查彼此重疊及獲焦、懸停後的實際尺寸；逐一選取真實長度的內容，再確認固定返回仍可見。短資訊分組不代表可以省略完整操作入口。[地圖反例與可重播流程](../design/runtime/island-map-target-layout.md)。
- 結算分頁要用真實長度的明細、資格說明與部分末頁驗證照片和視窗穩定；短標籤合成資料通過可能沒有觸發最小寬度／高度差異。先保存不能重現的診斷，再以同一個可重現反例比較舊／新版，不改門檻湊通過。
- 操作提示須避開動態主體的完整擺動範圍，並在後續排版刷新、極端姿勢與降低動態下重新確認。教學圖同步更新為現行實際操作與結果畫面，保存來源截圖與逐檔指紋，避免教學仍顯示舊版光影或介面。
- 使用者指定多看**《歧路旅人》與《幻想水滸傳》**及其他 HD-2D／2D 成熟案例，學閱讀、層次與操作方法，不直接挪用美術。

### 明確否定的 UI 反例

## 8. 小遊戲：每一款都要值得存在

- 同一園區統一主題，不等於每款共用場地、鏡頭、動畫和畫面再換規則。依玩法選純 2D、2.5D、HD-2D 或 3D，追求讓玩家耳目一新的不同體驗。
- 目標、操作手感、主動決策、分數、成功／失誤與結算回饋需專業且清楚；並列比較十二款，不能只逐款宣稱好玩。
- 氣球快遞曾被指出無聊、操控弱、引導弱，「有海風」卻看不到。風要可見、可預判且實際影響玩法，玩家能主動操控，教學逐步建立理解。
- 特效、視差、風與命中回饋取自同一套玩法狀態，不做與操作無關的假演出；提示避開操作主體。
- 結算逐輪說清楚得分資格及零分原因；只列實際完成的段落，不替未完成的操作補成果。原生驗收分別走普通、精準、失敗、重試與私人練習，實際點開全部結果分頁；保存原失敗／拒收版本，保留原操作、計分及時間門檻。
- 資格規則要在玩家實際看到的結算上說清本次原因，不能只存在資料或遊戲中明細。結果翻頁時，少量末頁內容不應讓照片、視窗或返回按鈕跳動；保留穩定空間，字級／視窗切換時再依新容量量測。實際點開每頁比對照片位置與完整文字。[風箏前後、六方參考及真輸入紀錄](../design/runtime/kite-flight-design.md)。
- 每款小遊戲有自己的遊戲內成就，每園區通關與全小惡魔收集等也有成就；預留 Steam 接口，未得到平台確認不寫成已同步。
- 專案長期基線：單人中心，可擴充 1–4 人同機與 P2P，簡單 AI 也能取得全內容；至少 100 款基本小遊戲，目前 128 候選，異空間變體不湊數。十區普通拍貼 180 開終區，每區 12 惡魔拍貼開當區異空間，收藏不消耗。這些長期數字不代表目前程式已具備全部內容。

## 9. 聲音與音樂

- 背景音樂與音效**全部使用可核對的 CC0**；免費、免版稅不等於 CC0。保留作者、原始授權頁、來源檔與雜湊。
- 用心挑真正適合島嶼、角色、動作與玩法的音色／節奏；各小遊戲與結算不能永遠共用同一段音樂。
- 留意循環接縫、切換、連續命中、失誤、對話與多聲疊加。對話滴滴聲克制，音量、靜音、暫停、重試及重新進場需正常。
- 必須實際試聽後才判斷舒適度與適配性。RMS、非零 PCM、音量值或成功載入只證明技術輸出，不代表音色好聽。

### 共通研究與製作流程

1. 動手前讀本指南、本票最新內容與相依，核對真正的遊戲版本及已拒收候選。
2. 每個主題比較至少六個不同來源；視覺問題優先找可實際對照的圖例或演出。Xbox／Game Accessibility Guidelines 可供操作及可及性參考，但不能代替美術、動作、遊戲性與介面案例。
3. 保存有助於決策的參考原圖或實際頁面截圖，附原始頁、作者／團隊、擷取方式、觀察與採用理由；與遊戲素材、玩家喜好圖、生成候選及實際驗收截圖分開標示。
4. 先做範圍完整的小批，核對正常速度、真正慢速及完整畫面；數值檢查與實際看圖互相補足，失敗候選留原因。必要動作／方向／影格的清單獨立於目前可用素材，不能刪掉整段缺件後就變成「全部通過」。
5. 分割／材質標記草稿若在抬手、持物或換向時誤標，就回到可編輯分層原件或明確作者標記；不反覆擴大執行時的顏色猜測，也不把一個方向的成功擴稱為全套覆蓋。通過起停、切換、暫停、降低動態與匯出包等相應回歸後，再擴下一款。只做過靜態圖、抽幀或資源包，就照實記錄，不寫成影片連續播放、真人試玩或平台完整驗收。
6. 本票記問題、可見改動、採用流程、結果及證據；跨多張票重用的規則整理回本指南，具體參數與技術細節放設計文件。

衣料來源若畫著持物袖子，擺臂後的衣身底料需完整；不能把原姿勢的袖子排除範圍套到獨立衣身。原手、道具、背包及衣服的邊界要分別審閱，過寬的相機保護框可能連短褲一起保留，僅由色塊或近似骨頭範圍推測也可能切去袋身或手掌。數值通過仍有接縫／遮擋破綻就保留拒收，不增加已批准覆蓋，更不把不同款式的草稿格數相加。[本輪六方研究、反例與拒收紀錄](../design/runtime/outfit-completeness.md)。

製作候選需要檢視時，提供明確的單格檢視入口並保留來源／圖框／錨點驗證；它不代表整套已通過或已進入正式衣櫃。檢視快取和正式角色的布局分開，另用回歸確認看過候選後不會污染正式人物。介面遷移保留原本可觀察的斷言，補上正式來源仍安全的檢查；不以刪測試或回復拒收素材來處理。見 [ART-18 衣物契約](../design/runtime/outfit-completeness.md)。

角色圖若做固定畫布平移，與該原圖共用座標的裁切框、髖點、保護區及取樣位置也要套用同一份已登錄位移；每次從不可變原資料複製，避免重建或換裝時累加。借用別張圖的色樣使用那張圖自己的位移；獨立鞋圖／配件圖集保留自己的座標。不要用修改測試預期值或挪回角色根點處理校準差異。[座標契約與六方研究](../design/runtime/source-registration-contract.md)。

本批圖例可查 [ART-34 的定位前後、階層及 Slice 參考](Snapland-art/[ART-34]擴充島上其他髮型動態.md) 與[圖片來源紀錄](Snapland-art/images/ART-34-reference-provenance.json)。都是已檢視的官方靜態原圖；沒有把參考角色當作自有遊戲素材。

### 角色完整性與場景遮擋

來源圖框、透明邊距、足底接地、鏡頭範圍與場景遮擋分開驗收。物件四角在畫面內、物理射線沒撞到或腳錨數值正確，都不能證明手腳未被沒有碰撞的花葉／裝飾擋住。原生畫面先實看；必要時在相同鏡頭／姿勢／光照下比對正常場景、僅人物及空底的實際像素，使用空閒檢視層並完整復原狀態。保留故意移回舊站位的失敗反例，優先調整可讀的站位與互動點，不把關閉深度當遮擋修正。原生完整性檢視直接把新圖與像素報告放在本次隔離存檔旁，避免預設寫回票內歷史圖片。[六方比較、方法及本作前後圖](../design/runtime/sprite-rendered-clearance.md)。

- Git 作者與提交者都必須是 `Stanley Li <stanley890314@gmail.com>`，每次 commit 後分別核對兩者。訊息只寫票號與具體變更，不含模型名稱、`Co-Authored-By`、`Claude-Session` 等行；只設專案設定。

- 測試成功需同時有正確退出狀態、沒有引擎 ERROR、以及本測試的實際完成行。正常退出或引用成功字串不等於測試完成；來源圖集診斷的名稱也不能擴稱為正式播放驗收。契約與入口反例先於昂貴引擎流程執行，避免缺測或舊訊息等到整套後段才被發現。見[六方比較與實際診斷圖](../design/runtime/runtime-result-contract.md)。
- 測試、截圖、錄影、匯入與預覽一律用**獨立絕對存檔路徑**，不得碰正式進度或拿測試檔冒充復原。原生輸入驗收需涵蓋事件傳遞，不只直接呼叫處理方法。新證據先跟隨隔離存檔保存，檢查後再挑本批成果放票內，不直接覆寫共享的舊證據。
- 多尺寸輸入需將控制項的 viewport 座標轉成實際視窗座標，傳遞視窗 ID、滑鼠移動、按下／放開與緩衝事件；不能拿邏輯位置直接當實體點擊。視窗尺寸、實際渲染圖片尺寸與桌面錄影尺寸分別記錄，含固定比例留邊時尤其如此。
- 每個測試套件隔離整個存檔父資料夾，包含照片、縮圖、快取、備份與反例子程序；不同JSON檔名仍可能共用同一份photos。用保護檔核對前套件產物不被讀到／覆寫，不能靠清掉其他套件檔案或放寬數量斷言通過。[六方比較與真引擎前後反例](../design/runtime/runtime-profile-isolation.md)。
- 新程序重開驗收要關閉引擎再啟動，保存完整前後進度位元及照片共用路徑。影片需有可解碼的完整檔案；錄影工具受控停止與遊戲退出分開判讀，抽樣檢視不能寫成完整連續觀看。
- 測試量測副本與暫存素材跟隨本次隔離存檔目錄，不只依賴 Windows 的 TEMP；空白或相對存檔路徑應明確失敗。獨立比對需先回到同一畫布座標，再比較原有量測常數，不能拿登錄前裁切框直接比登錄後原圖。
- 分清 SceneTree／MainLoop 腳本與 Node／Control 場景入口；不要把一般 `.gd` 當可執行入口，也不直接執行 `.review/commit-slices` 快照。不把 `--check-only` 當一般介面腳本的安全入口。
- 真正看過畫面後，截圖／影片放 `pm/<專案>/images/`；票用「問題—改動—驗收」白話文，附來源、測試摘要、分支與遠端提交，只有真正通過才勾選。
- 每次 push 前執行 `git fetch origin main`。若 main 前進，先把本工作分支 rebase 到最新 `origin/main`，保留其他 Session 的修改、解衝突並重跑受影響的必要測試。
- 使用者指定的 merge 是 `git push origin HEAD:main` 快轉整合本票到最新 main，禁止 force push main。若只因 main 又前進而非快轉拒絕，重新 fetch／rebase 後正常推送；403／權限拒絕不重試、不繞過，回報具體原因。
- 每票推送後 fetch，確認本機 main 與 origin/main 一致。更新本機 main 前先核對其 checkout 與未提交內容；不能 reset、強改其他 Session 使用中的分支。無法安全同步就回報具體阻塞，不宣稱已同步。
- 全部交付後只清理本 Session 已確認合入最新 main 且不再使用的 worktree、工作分支及對應遠端舊分支；不得刪其他 Session 或未合併分支，遠端拒絕刪除就停止並回報。逐票交代結果、測試、證據、提交、票況與缺口。

新證據跟隨獨立存檔保存；真正查看後再按票複製，勿覆寫舊截圖。UI合成收藏／結算只驗布局與導覽，不冒充自然通關；舊Windows圖已另核對實際尺寸，不能由這次雲端問題推論全部舊圖無效。ART-23開始逐票結案，最新票數以open_tickets為準；ART-20拍貼實際遊園流程與MAIN-10當前教學資產仍依原票。


測試基準隨正式原畫更新時，先查實際來源、透明門檻與場景入口，不直接改魔術數字。製作候選要在隔離fixture明確啟用，正式世界另驗沒有候選；舊素材比例真的不合時，保留失敗再修素材。2D混合alpha與3D裁切shader門檻不同，不能全域套同一值。泡泡照片的實際角色大小須在首張snapshot之前同步，路線覆蓋另以中心旅行及三輪finished驗證。詳見MAIN-2本輪契約。


保存驗收要區分同一程序重新載入與真正退出重啟。新增MAIN-6可選兩程序場景：writer退出後reader用不同PID核對完整樹與存檔位元組；全部用隔離絕對路徑，不以一個欄位或UI預覽替代。平台SDK未接入時只聲稱遊戲內成就／待同步事件保存，不能聲稱Steam已收到。見[流程與六份比較](../design/runtime/progress-restart-verification.md)。MAIN-6已依本輪證據結案，最新票況以open_tickets為準。


非16:9尺寸另外核對內容和留白：800×600視窗可能含800×450內容，上下各75px。直接擷取完整原生client window，不放大viewport圖；PNG尺寸讀Image／檔案本身，報告另列內容尺寸。ART-8本輪八頁及33頁流程附票，舊Windows圖仍屬歷史證據。


### 完整人物動作與匯出來源一致性

新專用待機會改變比較基準，過去通過的動作仍需重新核對身份／比例。本輪ART-17／SG-20接帽使用同一完整人物格，不按每格alpha或鞋底重套身體比例；動作來源、實際眼睛、手掌及衣料責任分開驗。資料id要從正式衣櫃讀取，`bob`才是短髮，無效id落回原髮型不能算該款測過。

來源hash精確比較也要涵蓋實際匯入與PCK：第一份新圖匯入改了弱alpha邊緣RGB，不能直接放寬hash。保留原圖像素、重新匯入並在沒有散落PNG的PCK重驗。共用owner新增另一動作會使已完成髮型的依賴失效；先重新匯出原16方向的遮罩／walk-idle聯集，確認根點、所有權與cut全數相同，才重建依賴。這一輪96組實際渲染及200格休止比較通過。

站定全身動作不能沿地滑行；移動保留真正走路及操作提示，停止不從半途續播被中斷的手勢。驗收站姿用獨立無獎勵演練，再驗正式局移動與接帽同時存在，不為了截圖鎖住正式局輸入。[完整方法、七方來源及限制](../design/runtime/catch-character-consistency.md)。


### 結算閱讀與原生驗收補充（SG-22）

分數、步數與完成數的單位要分開：不額外加分的紀錄欄仍顯示真實次數，不能一律呈現 0 分。解題遊戲列出各工單的目標與實際表現，讓一般、精準及部分失敗能從畫面核對；明細不要在大面積留白下硬切成很多頁，小視窗和大字則驗證每頁完整內容與返回。原生素材以絕對隔離存檔的父目錄輸出，使用遞增序號且拒絕覆寫；記錄實際模型時間、牆鐘、輸入、結果與保存影響。失敗或逾時路線不能改時鐘／分數／結果旗標，先檢查原因再重跑，保留原始失敗紀錄。

### 2026-10-21 解題結算與試玩路線

解題型玩法先核對真正的普通／精準條件，再做結算。每桌／每輪列出能解釋結果的實際表現，不把有影響得分的步數稱為「不計分」。自動重排與開始新局分開：前者保留當局錯誤歷史與精準資格限制，後者清掉整局狀態。耐心解題若用盡額度會重排，就實際驗重排，不憑空另加倒數或失敗面板。投影類則保留真正的光源、輪廓誤差與原判定，精準／合格／失誤在結果上可分辨。

原生驗收同時做最短／精準、一般完成、錯誤恢復及私人練習；結果重試在真實按鈕事件當下核對歸零，完成前或失敗後以完整非空存檔位元組驗安全。首次完整教學、重看與離開再進入另用新玩家檔，不能由已讀 fixture 的通關推論。低 FPS 錄影若輸入腳本在目標兩側振盪，先檢查按鍵保持時間與細調使用時機；記錄拒收，再修測試操控策略，不放寬正式判定、延長原限制或強制設位置。各款實際結果仍須原生查看。

自然活動的接地驗收須保留真正運行的NPC，不把強制凍結／指定姿勢圖當自然短片。用實際可見原畫透明像素獨立投影到地形，並分清玩家取景定位、NPC自然動作、正式完整方向覆蓋及打包資源啟動各自能證明的範圍。[本輪ART-12紀錄](Snapland-art/[ART-12]安排角色站位與個性動作.md)。


### 固定步長與慢放驗收

Godot 會從腳本可讀的命令列移除已解析的引擎選項。彩帶／合奏的固定步長驅動器須同時傳入引擎 `--fixed-fps 60` 與使用者參數 `-- --review-fixed-clock`，不能靠重新搜尋引擎參數來判斷模式。慢放的影格等待須按實際時間倍率換算，仍保留有限影格／程序上限；不改計分、命中窗口或模型時間來讓驗收通過。保留原始失敗，一段正式回合通過不能蓋掉後面的練習失敗。[已查證的時鐘與等待流程](../design/runtime/native-review-clocks.md)。固定模擬／軟體渲染不是即時硬體效能或實際試聽。

### 純衣料與舊動作覆蓋

覆蓋表須分開「原畫格」和「實際呼叫」：同一舊慶祝圖被24次呼叫不等於24張新動畫。缺少髮材質owner的來源，不可借整片保護區開放換髮；製作衣料只能對精確來源證明原上半身完全不變，並驗衣料alpha未侵入。單格衣料縮放不得移動／縮放原人物。先看來源、衣料與合成全身，再做染色及髮帽整合；數字齊全不代表可上架。[ART-18本輪方法與拒收](../design/runtime/outfit-completeness.md)。

正式衣物整合要保留原身體作為外觀與頭部責任來源；純衣料疊在染色之後、髮帽之前，整套來源指紋確認後才顯示，缺任何格就整套回退。本輪ART-18長背心已通過原生衣櫃與保存，成為免費基礎收藏；製作入口仍只報inspection，不由作者自己升格。Godot會重映射匯入圖片，若需要原位元組驗證，須保存不經圖片匯入的資料並在沒有散落素材的包內重驗。輸出驗收也須尊重已保存的降低動態，核對停播狀態，不為了通過smoke打開玩家已關閉的裝飾。[正式整合與首輪失敗](../design/runtime/outfit-completeness.md)。

沿路玩具用「進入踏板才觸發、離開才重新準備」控制，不把站定等待變成自動連發；附近原互動鍵也操作同一物件，避免強迫精準走位。狀態只保留在場景，不發分數／拍貼、不寫進度。先驗暫停、失焦、降低動態與完整存檔，再以真正往返路線檢查是否塞住道路。面板已有狀態列的結果不要再浮到世界路標上。[MAIN-11踏板風車流程與三方追加研究](../design/runtime/island-reactive-story.md)。


目錄新增商品時，分頁回歸須以獨立商品身份集合核對「保留列」與「實際翻頁可達列」，同時擋住漏列、重複列及半截列；不要只把舊的固定總數改大。保留既有商品、免費外觀與零幣可穿戴的檢查，並重跑小視窗／大字級整條操作路線。CI失敗先保存原log並重現，修正後保留反例和成功結果。[ART-18目錄回歸](Snapland-art/[ART-18]同步換裝分層與角色動畫.md)。


角色投影須讀取最後顯示的整體貼圖，不另建髮帽的動作時鐘；原人物畫布、頭部錨點與碰撞保持原責任。直立的投射面保留可見人物的世界高度，避免跟拍鏡頭傾角變成腳邊的地面偏移。先驗透明輪廓／方卡反例、圖集及同一動態貼圖的更新，再用正式世界四時段、接地／光向與離開／重入驗收。降低動態截圖記錄拍攝當下設定，不能只信檔名。[ART-1方法與拒收](../design/runtime/character-lighting-shadows.md)。

大量原生截圖可用無損容器保存，但每張解碼RGBA都須核對原像素雜湊，另留原PNG位元組指紋及透明PNG。矩陣是圖片儲存，不是動畫影片；正常／慢放仍須真正錄製與檢視。重建PNG壓縮位元組可不同，像素不可變；小幅縮圖或有損影片不能代替原尺寸像素驗證。[本輪可還原證據與工具](Snapland-art/images/ART-1-upright-20261024-replay.zip)。


### 舊素材退役的核對

舊需求被新場景完整取代時，先確認所有實際入口，再在凍結動作、移除驗收遮罩的原生畫面比較「原圖／醒目替換／不畫」；仍有繪製呼叫時，另做移除覆蓋場景後能偵測變化的反向對照，避免無效截圖流程誤判。封存保留原未通過條件與原圖，雙向連結替代票，並清楚區分本輪新檢查與沿用的時段、輸出或玩法證據。ART-19 的十二入口核對可作範例。


角色步行候選先以「相反接觸姿勢確實交換承重腿」作門檻，再檢查下沉、跨步、推離及首尾接續；格數、文字標籤或鞋襪換色不能證明步態正確。修改一格後也要重新看整輪，避免修好推離卻改壞跨步。透明素材至少在白底及預期遊戲底色合成覆核，不能因黑底預覽的隱藏 RGB 就誤判背景光暈。ART-17 保存本次圖解、提示詞及拒收對照。


衣料資源先驗整套，與常駐持有全部解碼圖是兩回事。整套通過後可按需載入並設定明確快取上限，回載再驗精確來源；回退狀態也必須傳到最終角色貼圖，不能由舊快取復活已拒收衣物。驗證包含冷／暖、淘汰／回載、實際刪檔／改檔與發行包；記憶體數字要說清楚是衣料畫布、暫存或整個程序。[ART-18 可重現方法與反例](../design/runtime/outfit-resource-cache.md)。
